# 2단계 7장. 미니 프로젝트: 도서 대출 목록 완성

> **실행 환경: 도커.** 명령 블록은 컨테이너 안(bash)에서 칩니다. `[Windows]` 로 표시된 블록만 Windows PowerShell 에서 칩니다. 파일 편집은 Windows 의 VS Code 에서 합니다. 자세한 설명은 [도커로 실행하기](../docker/00_도커로_실행하기.md)를 봅니다.

| | |
|---|---|
| 시간 | 2시간 30분 |
| 준비물 | 1~6장 완료 |
| 결과 | 새 폴더에서 처음부터 도서 대출 목록을 AI 에게 맡기고, 테스트와 직접 실행으로 확인한 뒤 저장한다. 과정 기록을 쓴다 |

> 이 장은 **정답 파일을 주지 않습니다.** 요구사항과 테스트를 기준으로 확인합니다.

## 이 장에서 할 일 한눈에 보기

1. 새 작업 폴더를 만들고 기준 파일을 가져온다. (15분)
2. 요구사항과 테스트 이름을 대조한다. (20분)
3. AI 에게 맡기고 계획을 검토한다. (25분)
4. 검증하고 테스트 파일을 대조한다. (15분)
5. 직접 실행해서 확인한다. (20분)
6. 기록을 쓰고 저장한다. (25분)

## 1단계. 새 작업 폴더 만들고 기준 파일 가져오기 (15분)

**[컨테이너]**

```bash
mkdir -p /workspace/library-final/tests /workspace/library-final/.githooks
cd /workspace/library-final
cp /tutorial/templates/stage2/tests/test_books.py tests/
cp /tutorial/templates/stage2/tests/test_lending_v2.py tests/test_lending.py
cp /tutorial/templates/stage2/REQUIREMENTS.md .
cp /tutorial/templates/stage2/TASK_미니프로젝트.md .
cp /tutorial/templates/stage2/pytest.ini .
cp /tutorial/templates/verify.py .
cp /tutorial/templates/opencode.jsonc .
cp /tutorial/templates/pre-commit .githooks/pre-commit
cp /tutorial/templates/.gitattributes .
cp /workspace/library/AGENTS.md .
printf 'books.json\n.env\n' > .gitignore
git init
git config core.hooksPath .githooks
ls -la
ls tests
```

확인 기준: 아래 표의 파일이 모두 있어야 합니다.

| 파일 | 있는가? (예/아니오) |
|---|---|
| REQUIREMENTS.md | |
| TASK_미니프로젝트.md | |
| AGENTS.md | |
| opencode.jsonc | |
| verify.py, pytest.ini | |
| tests/test_books.py, tests/test_lending.py | |
| .githooks/pre-commit | |

확인 기준 2: `git config core.hooksPath` 가 `.githooks` 를 출력해야 합니다.

## 2단계. 요구사항과 테스트 이름 대조하기 (20분)

**[컨테이너]**

```bash
cd /workspace/library-final
grep -n "^### R" REQUIREMENTS.md
grep -n "^def test_" tests/test_books.py tests/test_lending.py
```

아래 표를 채웁니다. 요구사항 한 개에 테스트가 **적어도 하나** 있어야 합니다.

| 요구사항 | 요구사항의 함수 이름 | 이 요구사항을 확인하는 테스트 이름 (두 번째 명령의 출력에서 찾는다) |
|---|---|---|
| R1 책 등록 | add_book | |
| R2 목록 보기 | list_books | |
| R3 대출 | lend_book | |
| R4 반납 | return_book | |
| R5 파일 저장과 읽기 | save_books, load_books | |

확인 기준: 다섯 줄이 모두 채워져야 합니다. 빈칸이 있으면 그 요구사항에 테스트가 없다는 뜻입니다. `REQUIREMENTS.md` 를 고치지 말고 강사에게 알립니다.

## 3단계. AI 에게 맡기고 계획 검토하기 (25분)

**[컨테이너]**

```bash
cd /workspace/library-final
opencode
```

**[AI]**

```text
TASK_미니프로젝트.md 를 읽고 그 지시대로 작업해 줘. REQUIREMENTS.md 와 tests/ 를 기준으로 삼는다. 먼저 계획만 말하고 내 승인을 기다려.
```

계획을 아래 네 질문으로 검토합니다.

| 질문 | 답 (예/아니오) | 아니오면 입력할 문장 |
|---|---|---|
| 1. 고치는 파일이 library.py 한 개뿐인가? | | 아래 문장 A |
| 2. 계획에 R1~R5 의 함수가 모두 들어 있는가? | | 아래 문장 A |
| 3. 계획에 책 삭제, 연체, 웹 화면, 데이터베이스가 없는가? | | 아래 문장 A |
| 4. 계획이 tests/, REQUIREMENTS.md, verify.py 를 고친다고 하지 않는가? | | 아래 문장 A |

**[AI] 문장 A** (아니오일 때, 번호만 바꿔 입력합니다)

```text
계획 [번호]번이 TASK_미니프로젝트.md 와 맞지 않아. 그 부분을 고쳐서 계획을 다시 말해 줘. 아직 파일은 만들지 마.
```

모두 예이면 입력합니다.

**[AI]**

```text
진행
```

끝나면 `/exit` 를 칩니다.

## 4단계. 검증하고 테스트 파일 대조하기 (15분)

**[컨테이너]**

```bash
cd /workspace/library-final
python verify.py
diff tests/test_books.py /tutorial/templates/stage2/tests/test_books.py && echo "책 테스트 원본과 같습니다"
diff tests/test_lending.py /tutorial/templates/stage2/tests/test_lending_v2.py && echo "대출 테스트 원본과 같습니다"
git status
```

확인 기준:

| 확인할 것 | 기대하는 결과 | 실제 결과 (예/아니오) |
|---|---|---|
| 검증 | "검증 통과"로 끝난다 (`13 passed`) | |
| 책 테스트 대조 | "책 테스트 원본과 같습니다" | |
| 대출 테스트 대조 | "대출 테스트 원본과 같습니다" | |
| git status | 새로 생긴 파일이 library.py 뿐이다 | |

아니오가 있으면 AI 에게 그 항목을 알리고 고치게 합니다. 테스트 파일이 바뀌었다면 원본을 다시 복사합니다.

## 5단계. 직접 실행해서 확인하기 (20분)

**[컨테이너]**

```bash
cd /workspace/library-final
python -c "
from library import add_book, lend_book, return_book, list_books
books = []
add_book(books, '데미안', '헤세')
add_book(books, '노인과 바다', '헤밍웨이')
lend_book(books, 1, '철수')
print('1. 대출 중 목록:', [b['title'] for b in list_books(books, 'lent')])
print('2. 대출 가능 목록:', [b['title'] for b in list_books(books, 'available')])
print('3. 반납 후:', return_book(books, 1))
try:
    return_book(books, 1)
    print('4. 대출 중이 아닌 책 반납: 오류가 없었다 (잘못됨)')
except ValueError as e:
    print('4. 대출 중이 아닌 책 반납: 오류 =', e)
"
```

확인 기준:

| 줄 | 기대하는 결과 | 실제 출력 (그대로 옮긴다) | 맞는가? (예/아니오) |
|---|---|---|---|
| 1 | 대출 중 목록에 "데미안"이 한 개 | | |
| 2 | 대출 가능 목록에 "노인과 바다"가 한 개 | | |
| 3 | 반납 후 status 는 available, borrower 는 None, loan_days 는 없다 | | |
| 4 | "오류 ="이 나온다 | | |

아니오가 있으면 AI 에게 그 줄 번호를 알리고 고치게 합니다.

## 6단계. 기록 쓰고 저장하기 (25분)

**[컨테이너]**

```bash
cd /workspace/library-final

```

**[Windows]** VS Code 에서 `C:\harness-lab\library-final\기록.md` 를 열고 아래 틀을 붙여 넣습니다.

```markdown
# 7장 기록

## 1. 이 프로젝트에서 바뀐 요구사항 한 가지와, 왜 기준을 사람이 바꿨는가
답:

## 2. 검증은 통과했지만 범위를 대조해서 확인한 것 한 가지
답:

## 3. 되돌리기를 했다면 어떤 방법을 썼고, 왜 그 방법을 골랐는가 (없으면 "없음")
답:

## 4. 내가 이해한 코드 세 문장
1.
2.
3.

## 5. 2단계를 마치고 1단계와 달라진 점 한 가지

```

확인 기준: 모든 `답:` 뒤에 글자가 있어야 합니다.

**[컨테이너]**

```bash
cd /workspace/library-final
grep -c "^답:\s*$" 기록.md
```

`0` 이면 저장합니다. 저장은 사람이 합니다.

**[컨테이너]**

```bash
cd /workspace/library-final
python verify.py
git add -A
git status

```

확인 기준: `git status` 에 `books.json` 이 없어야 합니다. 커밋 과정에서 `[pre-commit]` 이 "검증 통과"를 출력해야 합니다.

## 막혔을 때

| 증상 | 해결 |
|---|---|
| `cp` 가 "No such file" 이라고 한다 | `ls /tutorial/templates/stage2` 로 파일 이름을 확인한다. |
| 테스트가 `ImportError` 를 낸다 | `library.py` 에 함수 이름이 빠졌다. 2단계 표의 이름을 AI 에게 알리고 추가하게 한다. |
| AI 가 `tests/` 나 `REQUIREMENTS.md` 를 고치려 한다 | 기준은 사람이 고친다. AI 에게 "기준 파일은 고치지 마"라고 말하고, `diff` 로 확인해 되돌린다. |
| 직접 실행 4번 줄에 "오류가 없었다"가 나온다 | 대출 중이 아닌 책의 반납을 막는 검사가 없다. AI 에게 "대출 중이 아니면 ValueError 를 일으키게 해 줘"라고 말한다. |

> 정답 코드는 제공하지 않습니다. 실패 줄을 하나씩 읽고, AI 와 대화하며 맞춰 갑니다.
