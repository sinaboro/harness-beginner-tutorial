# 2단계 7장. 미니 프로젝트: 도서 대출 목록 완성

> **실행 환경: 도커.** 명령은 컨테이너 안(bash)에서 칩니다. 교안의 PowerShell 명령은 [도커로 실행하기](../docker/00_도커로_실행하기.md)의 명령 대응표(4절)를 보고 바꿔 씁니다. 편집은 Windows 의 VS Code 에서 합니다.

| | |
|---|---|
| 시간 | 2시간 30분 |
| 준비물 | 1~6장 완료 |
| 결과 | 도서 대출 목록을 처음부터 다시 만들고, 검증과 저장을 거쳐 완성한다. 과정 기록을 쓴다. |

## 학습 목표
1. 1~6장의 요소(요구사항, 지시서, 기준, 변경, 검증, 되돌리기)를 한 번에 쓴다.
2. 요구사항 변경이 반영된 최종 기준을 사람이 확인하고 AI 에게 구현시킨다.
3. 범위와 검증, 두 가지를 모두 확인하고 저장한다.

---

## 1. 개념 — 지금까지의 고리

```text
 ① 요구사항 (REQUIREMENTS.md, 변경 반영 완료)   1장 · 5장
 ② 기준 (tests/, 사람이 준비)                   2장 · 3장 · 5장
 ③ 작업 지시서 (TASK_미니프로젝트.md)            3장
 ④ 규칙과 권한 (AGENTS.md, opencode.jsonc)      1단계 4장
 ⑤ 검증과 범위 확인 (verify.py, 요구사항 대조)   4장 · 6장
 ⑥ 저장 또는 되돌리기 (git commit, revert)      2장 · 6장
```

이번 장은 **새 폴더에서 처음부터** 합니다. 2~6장의 `library.py` 를 가져오지 않습니다.

---

## 2. 따라 하기

### 1단계. 새 폴더와 최종 기준 준비하기 (15분)

**[PS]**

```powershell
New-Item -ItemType Directory C:\harness-lab\library-final
New-Item -ItemType Directory C:\harness-lab\library-final\tests
cd C:\harness-lab\library-final
git init
git config core.hooksPath .githooks

$T = "C:\harness-beginner-tutorial\templates"
Copy-Item "$T\stage2\tests\test_books.py" tests\
Copy-Item "$T\stage2\tests\test_lending_v2.py" tests\test_lending.py
Copy-Item "$T\stage2\REQUIREMENTS.md" .
Copy-Item "$T\stage2\TASK_미니프로젝트.md" .
Copy-Item "$T\stage2\pytest.ini" .
Copy-Item "$T\verify.py" .
Copy-Item "$T\opencode.jsonc" .
Copy-Item "$T\AGENTS_빈칸.md" AGENTS.md
New-Item -ItemType Directory .githooks
Copy-Item "$T\pre-commit" .githooks\pre-commit
Copy-Item "$T\.gitattributes" .
Set-Content .gitignore "books.json`n.env"
dir tests
```

> `tests\test_lending.py` 는 2차(대출 기간 포함) 기준입니다. 5장에서 승인된 최종 기준이기 때문입니다.

### 2단계. 요구사항 확인하기 (15분)

`REQUIREMENTS.md` 를 읽고 아래를 표시합니다.

- [ ] R3 의 대출에 `loan_days` 14 가 들어 있다.
- [ ] R4 의 반납에 `borrower` 를 `None` 으로 바꾸고, `loan_days` 를 지운다.
- [ ] "만들지 않는 것"에 책 삭제와 연체가 있다.

이 요구사항과 `tests\test_lending.py` 가 같은 말을 하는지 대조합니다. 다르면 **요구사항이 아니라 기준을 바꿀지 먼저 결정합니다.** (변경 요청서가 필요합니다)

### 3단계. AI 에게 맡기기 (30분)

**[PS]**

```powershell
opencode
```

**[AI]**

```text
TASK_미니프로젝트.md 를 읽고 그 지시대로 작업해 줘. REQUIREMENTS.md 와 tests/ 를 기준으로 삼는다. 먼저 계획만 말하고 내 승인을 기다려.
```

계획을 검토합니다.

- [ ] `library.py` 하나만 만들겠다고 했는가?
- [ ] R1~R5 가 모두 계획에 있는가?
- [ ] 책 삭제, 연체, 웹 화면, 데이터베이스가 있는가? (있으면 뺀다)

맞으면 `진행`. 끝나면 `/exit`.

### 4단계. 검증 두 가지 하기 (25분)

**(1) 기계 검증**

**[PS]**

```powershell
python verify.py
```

"검증 통과"가 나와야 합니다.

**(2) 범위 검증 (사람이 한다)**

`library.py` 에 함수 이름을 모두 나열합니다.

**[PS]**

```powershell
Select-String "^def " library.py
```

요구사항의 기능과 하나씩 대조합니다.

| 함수 | 요구사항 | 있어야 하나? |
|---|---|---|
| add_book | R1 | |
| list_books | R2 | |
| lend_book | R3 | |
| return_book | R4 | |
| save_books, load_books | R5 | |
| (그 밖의 함수) | 없음 | 있으면 되돌린다 |

**(3) 직접 실행 확인**

**[PS]**

```powershell
python -c "from library import *; b=[]; add_book(b,'데미안','헤세'); add_book(b,'노인과 바다','헤밍웨이'); lend_book(b,1,'철수'); print(list_books(b,'lent')); print(return_book(b,1)); print(list_books(b,'available'))"
```

- [ ] 대출 중 목록에 "데미안"이 보인다.
- [ ] 반납한 책의 `borrower` 가 `None` 이고, `loan_days` 가 없다.
- [ ] 이미 대출 중인 책을 다시 빌리면 오류가 난다.

### 5단계. 문제가 있으면 되돌리거나 고치기 (15분)

범위 밖 함수가 있거나 직접 실행이 틀리면, 6장에서 배운 대로 합니다.

- 저장하지 않았다면: `git restore library.py` 후 지시서를 더 작게 나눠 다시 맡긴다.
- 저장했다면: `git revert` 로 되돌린다. (아직 저장하지 않았으므로 이 장에서는 해당 없음)

고칠 것이 있으면 AI 에게 말합니다.

**[AI]**

```text
범위 밖 함수 <이름> 이 있어. 요구사항에 없으니 지워 줘. 계획을 먼저 말하고, 내가 "진행"이라고 하면 library.py 만 고쳐 줘.
```

### 6단계. 저장하기 (10분)

**[PS]**

```powershell
python verify.py
git add -A
git status
git commit -m "7장: 도서 대출 목록 완성 (R1~R5, 검증과 범위 확인 완료)"
git log --oneline
```

`git status` 에 `books.json` 이 없어야 합니다. (`.gitignore` 에 있습니다)

### 7단계. 과정 기록 쓰기 (10분)

`기록.md` 를 만들고 아래를 채웁니다.

```markdown
# 7장 기록

## 1. 이 프로젝트에서 바뀐 요구사항 한 가지와, 왜 기준을 사람이 바꿨는가

## 2. 검증 통과와 범위 확인이 다르다는 것을 보여 준 장면 한 가지

## 3. 되돌리기를 했다면 어떤 방법을 썼고, 왜 그 방법을 골랐는가 (없으면 "없음")

## 4. 내가 이해한 코드 세 문장
1.
2.
3.

## 5. 2단계를 마치고 1단계와 달라진 점 한 가지
```

## 3. 확인하기
- [ ] 새 폴더에서 처음부터 만든 `library.py` 가 R1~R5 를 모두 지킨다.
- [ ] `python verify.py` 가 "검증 통과"다.
- [ ] 범위 밖 함수가 없다. (사람이 확인했다)
- [ ] 저장 커밋이 한 줄 생겼다.
- [ ] `기록.md` 를 썼다.

## 4. 막혔을 때

| 증상 | 해결 |
|---|---|
| 테스트가 `loan_days` 때문에 실패한다 | 요구사항 R3 와 `tests\test_lending.py` 가 같은 2차 기준인지 확인한다. |
| AI 가 `tests/` 를 고치려 한다 | 권한 설정이 막는다. 막히지 않았다면 `Compare-Object` 로 확인하고 되돌린다. |
| 계획에 연체 계산이 들어 있다 | TASK 의 "하지 말 것"을 가리키며 빼게 한다. |

> 이 장에서도 **정답 코드는 제공하지 않습니다.** 요구사항과 테스트를 기준으로 AI 와 대화하며 맞춰 갑니다.

## 5. 확인 문제
1. 최종 기준에 `loan_days` 가 들어간 것은 어떤 절차를 거쳐서였나?
2. 이 프로젝트에서 "검증 통과"만으로 끝내면 안 되는 이유를 예를 들어 설명하시오.
3. 2단계에서 가장 중요했던 하네스 요소는 무엇이었다고 생각하는가? 이유와 함께 쓰시오.
