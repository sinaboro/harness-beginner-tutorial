# 2단계 6장. 잘못된 변경을 되돌리기

> **실행 환경: 도커.** 명령 블록은 컨테이너 안(bash)에서 칩니다. `[Windows]` 로 표시된 블록만 Windows PowerShell 에서 칩니다. 파일 편집은 Windows 의 VS Code 에서 합니다. 자세한 설명은 [도커로 실행하기](../docker/00_도커로_실행하기.md)를 봅니다.

| | |
|---|---|
| 시간 | 2시간 |
| 준비물 | 5장까지 완료 (커밋 기록이 여러 줄 있다) |
| 결과 | 저장 전 변경은 `git restore` 로, 저장 후 변경은 `git revert` 로 되돌리고, 되돌린 뒤 검증한다 |

## 이 장에서 할 일 한눈에 보기

1. AI 에게 요구사항에 없는 기능을 시키고, 검증이 통과하는지 본다. (20분)
2. 범위를 대조해서 잘못을 찾는다. (15분)
3. 저장 전 변경을 `git restore` 로 되돌린다. (15분)
4. 같은 변경을 저장하고, `git revert` 로 되돌린다. (30분)
5. 되돌린 뒤 검증하고, 기록을 확인한다. (20분)

---

## 1단계. 요구사항에 없는 기능 시키기 (20분)

이 장은 **실수를 일부러 만드는 연습**입니다. 계획 검토를 건너뛰라고 말하는 것이 핵심입니다.

**[컨테이너]**

```bash
cd /workspace/library
git status
opencode
```

**[AI]**

```text
library.py 에 책 삭제 기능 delete_book(books, book_id) 를 추가해 줘. 계획 없이 바로 진행해 줘.
```

AI 가 끝나면 `/exit` 를 칩니다. 확인합니다.

**[컨테이너]**

```bash
cd /workspace/library
python verify.py
git status
grep -n "def delete_book" library.py
```

확인 기준:
- `python verify.py` 가 "검증 통과"로 끝납니다. (테스트는 깨지지 않았다)
- `grep` 이 `def delete_book` 줄을 찾습니다. (범위 밖 기능이 들어왔다)

## 2단계. 범위를 대조해서 잘못 찾기 (15분)

**[Windows]** VS Code 에서 `C:\harness-lab\library-req\요구사항.md` 를 엽니다. 1장에서 쓴 요구사항입니다. 이 파일이 이번 장의 기준입니다. 아래 표를 채웁니다.

| 질문 | 답 (예/아니오) |
|---|---|
| 1. 요구사항에 "책 삭제" 기능이 있는가? (`/workspace/library-req/요구사항.md` 의 "만들지 않는 것" 줄을 본다) | |
| 2. 검증이 통과했다는 것은 delete_book 이 맞다는 뜻인가? | |

확인 기준:
- 1번이 "예"이면, 삭제 기능은 "만들지 않는 것"에 적혀 있다는 뜻입니다. 범위 밖입니다.
- 2번은 **아니오**여야 합니다. 검증은 "적힌 약속을 지켰다"만 확인합니다. 약속에 없는 기능은 확인하지 않습니다.

> **이 장의 첫 번째 교훈:** "검증 통과"와 "범위 안에 있다"는 다릅니다. 범위는 요구사항과 지시서로 따로 확인합니다.

## 3단계. 저장 전 변경을 git restore 로 되돌리기 (15분)

**[컨테이너]**

```bash
cd /workspace/library
git status
git restore library.py
grep -c "def delete_book" library.py
python verify.py
git status
```

확인 기준:
- `git restore library.py` 뒤 `grep -c` 결과가 `0` 입니다.
- `python verify.py` 가 "검증 통과"입니다.
- `git status` 에 `library.py` 가 바뀐 것으로 보이지 않습니다.

> `git restore` 는 **저장하지 않은** 변경을 마지막 저장 상태로 돌립니다. 새로 만들어진 파일은 지워지지 않으므로 `git status` 의 `Untracked files` 를 보고 직접 지웁니다.

## 4단계. 저장 후 변경을 git revert 로 되돌리기 (30분)

이번에는 같은 실수를 **저장한 뒤** 되돌립니다.

**(1) 실수를 다시 만들고 저장하기**

**[컨테이너]**

```bash
cd /workspace/library
opencode
```

**[AI]**

```text
library.py 에 책 삭제 기능 delete_book(books, book_id) 를 추가해 줘. 계획 없이 바로 진행해 줘.
```

`/exit` 로 나온 뒤:

**[컨테이너]**

```bash
cd /workspace/library
python verify.py
git add -A
git commit -m "실험: 범위 밖 delete_book 저장"
git log --oneline
```

확인 기준: "검증 통과"가 나오고, `git log --oneline` 맨 위에 "실험: 범위 밖 delete_book 저장"이 있습니다.

**(2) 되돌리기 (기록은 남긴다)**

**[컨테이너]**

```bash
cd /workspace/library
git revert --no-edit HEAD
git log --oneline
grep -c "def delete_book" library.py
```

확인 기준:
- `git log --oneline` 에 두 줄이 생겼습니다. 하나는 "실험", 다른 하나는 "Revert" 입니다. **기록은 지워지지 않았습니다.**
- `grep -c` 결과가 `0` 입니다.

> `git revert` 는 되돌린 내용을 **새 커밋**으로 만듭니다. 원래 커밋을 지우지 않습니다. 그래서 "언제 무엇을 되돌렸는지"가 기록에 남습니다.

> 주의: `git reset --hard` 는 기록을 지우므로 이 과정에서 쓰지 않습니다. 이 과정의 AI 권한 설정도 `git reset` 을 막고 있습니다.

## 5단계. 되돌린 뒤 검증하고 기록 확인하기 (20분)

**[컨테이너]**

```bash
cd /workspace/library
python verify.py
git status
git log --oneline
```

확인 기준:
- "검증 통과"가 나옵니다.
- `git status` 가 깨끗합니다. (`books.json` 은 `.gitignore` 에 있으므로 보이지 않는 것이 정상)
- `git log --oneline` 에 "실험" 커밋과 "Revert" 커밋이 모두 있습니다.

**[Windows]** `C:\harness-lab\library\library.py` 를 열어 `delete_book` 이 없는지 눈으로 확인합니다.

## 6단계. 되돌리기 방법 고르기 (표 채우기, 15분)

아래 상황마다 무엇을 할지 고르고, 이유를 한 문장으로 씁니다. 선택지는 `git restore` / `git revert` / 아무것도 안 함 입니다.

| 상황 | 무엇을 하나 (선택) | 이유 (한 문장) |
|---|---|---|
| 방금 AI 가 바꾼 파일을 저장하기 전에 아니라고 판단했다 | | |
| 이미 저장된 커밋에 버그가 있다는 것을 어제 발견했다 | | |
| 테스트가 실패하지만 원인을 아직 모른다 | | |
| 3번 시도해도 검증이 통과하지 않는다 | | |

확인 기준: 네 줄 모두 선택과 이유가 있어야 합니다. 답이 맞는지는 강사와 함께 확인합니다.

## 7단계. 정리하고 확인하기 (10분)

**[컨테이너]**

```bash
cd /workspace/library
rm -f CHANGE_요청서.md
git status
```

확인 기준: `git status` 에 바뀐 파일이 없어야 합니다. 실험 커밋은 **지우지 않고 그대로 둡니다.**

## 확인 체크리스트
- [ ] `delete_book` 이 검증을 통과하는 것을 직접 봤다.
- [ ] 범위 질문 두 개에 답했다. (2번 질문은 "아니오")
- [ ] `git restore` 로 저장 전 변경을 되돌렸다.
- [ ] `git revert` 로 저장 후 변경을 되돌렸고, 기록 두 줄을 확인했다.
- [ ] 6단계 표를 채웠다.

## 자주 만나는 오류

| 증상 | 해결 |
|---|---|
| `git revert` 가 편집기를 연다 | `--no-edit` 를 빠뜨렸다. 편집기가 열리면 Esc 를 누르고 `:wq` 를 치고 Enter 를 누른다. |
| `git revert` 가 충돌을 알린다 | 되돌릴 커밋 뒤에 같은 줄을 또 고쳤다. `git revert --abort` 로 취소하고 `git log --oneline` 으로 순서를 확인한다. |
| `git restore` 후에도 파일이 남아 있다 | 새로 만들어진 파일이다. `git status` 의 `Untracked files` 에서 찾아 직접 지운다. |
| 되돌렸는데 검증이 실패한다 | 되돌리기 전 다른 변경이 섞여 있었을 수 있다. `git log` 와 `git diff` 로 확인한다. |
