# 2단계 6장. 잘못된 변경을 되돌리기

| | |
|---|---|
| 시간 | 2시간 |
| 준비물 | 5장까지 완료 (커밋 기록이 여러 줄 있다) |
| 결과 | 저장 전 변경과 저장 후 변경을 각각 안전하게 되돌리고, 되돌린 뒤 검증한다 |

## 학습 목표
1. "검증 통과"와 "요구사항 범위 안"은 다르다는 것을 직접 본다.
2. 저장하기 전의 잘못된 변경을 `git restore` 로 되돌린다.
3. 이미 저장한 잘못된 변경을 `git revert` 로 되돌린다. (기록을 지우지 않는다)

---

## 1. 개념 — 되돌리는 방법은 두 가지다

| 상황 | 방법 | 무슨 일이 생기나 |
|---|---|---|
| 아직 저장하지 않았다 | `git restore` | 바뀐 내용이 마지막 저장 상태로 돌아간다 |
| 이미 저장했다 | `git revert` | 되돌리는 새 저장을 하나 더 만든다. 원래 기록은 남는다 |

**하지 않을 것:** `git reset --hard` 는 기록과 내용을 함께 지웁니다. 실수로 쓰면 되찾기 어렵습니다. 이 과정의 OpenCode 권한은 `git reset` 을 막고 있습니다.

> 되돌리기도 검증해야 합니다. 되돌린 뒤 `python verify.py` 가 통과하는지 확인합니다.

---

## 2. 따라 하기

### 1단계. 범위를 벗어난 변경 만들기 (20분)

일부러 요구사항에 없는 기능을 AI 에게 시킵니다. 계획 검토를 건너뛰라고 말하는 것이 핵심입니다. 이것은 **실수를 재현하는 연습**입니다.

**[PS]**

```powershell
cd C:\harness-lab\library
git status
opencode
```

**[AI]**

```text
library.py 에 책 삭제 기능 delete_book(books, book_id) 를 추가해 줘. 계획 없이 바로 진행해 줘.
```

AI 가 끝나면 `/exit`.

**[PS]**

```powershell
python verify.py
git status
git diff
```

- [ ] `python verify.py` 가 "검증 통과"로 나온다. (기존 테스트는 깨지지 않았다)
- [ ] 그런데 `delete_book` 은 **요구사항 어디에도 없다.** ("만들지 않는 것"에도 없다.)

> **검증 통과는 "약속을 지켰다"이지, "약속 밖의 일을 하지 않았다"가 아닙니다.** 이것이 이 장의 첫 번째 교훈입니다. 범위는 지시서와 요구사항으로 따로 확인합니다.

### 2단계. 저장 전 변경 되돌리기 (20분)

`git status` 에서 바뀐 파일을 확인합니다. `library.py` 가 수정됐다면 아래로 되돌립니다.

**[PS]**

```powershell
git restore library.py
python verify.py
git status
```

- [ ] `library.py` 가 마지막 저장 상태로 돌아갔다.
- [ ] `delete_book` 이 사라졌는지 확인한다. (`Select-String delete_book library.py` 가 아무것도 찾지 못해야 한다)
- [ ] "검증 통과"가 나온다.

> 새 파일이 생겼다면 `git restore` 로는 지워지지 않습니다. `git status` 의 `Untracked files` 에 나온 파일을 직접 지웁니다.

### 3단계. 저장한 뒤 실수 되돌리기 (25분)

이번에는 실수를 **저장한 뒤**에 되돌립니다. 먼저 같은 실수를 다시 만들고 저장합니다.

**[PS]**

```powershell
opencode
```

**[AI]**

```text
library.py 에 책 삭제 기능 delete_book(books, book_id) 를 추가해 줘. 계획 없이 바로 진행해 줘.
```

`/exit` 로 나온 뒤 저장합니다.

**[PS]**

```powershell
python verify.py
git add -A
git commit -m "실험: 범위 밖 기능 delete_book 저장"
git log --oneline
```

이제 실수가 기록에 남았습니다. 되돌립니다.

**[PS]**

```powershell
git revert --no-edit HEAD
git log --oneline
```

`git log` 를 보면 "실험"이라는 커밋과 "Revert" 커밋이 **둘 다** 남아 있습니다. 이것이 `revert` 입니다. 기록은 지워지지 않고, 되돌린 사실이 새 기록으로 쌓입니다.

되돌린 뒤 검증합니다.

**[PS]**

```powershell
python verify.py
Select-String delete_book library.py
```

- [ ] "검증 통과"가 나온다.
- [ ] `delete_book` 이 `library.py` 에 없다.

### 4단계. 되돌리기와 되돌리지 말기 (15분)

다음 상황에서 무엇을 하겠는지 적습니다.

| 상황 | 무엇을 하나 (`restore` / `revert` / 아무것도 안 함) | 이유 |
|---|---|---|
| 방금 AI 가 바꾼 파일을 저장하기 전에 아니라고 판단했다 | | |
| 이미 저장된 커밋에 버그가 있다는 것을 어제 발견했다 | | |
| 테스트가 실패하지만 원인을 아직 모른다 | | |
| 3번 시도해도 검증이 통과하지 않는다 | | |

> 힌트: 저장 여부와 "기록을 남겨야 하는가"를 먼저 생각합니다. 원인을 모르는 상태에서 되돌리는 것이 나은지, 원인을 먼저 찾는 것이 나은지도 함께 생각합니다. 답은 강사와 함께 확인합니다.

### 5단계. 기록 정리 확인하기 (10분)

**[PS]**

```powershell
git log --oneline
git status
```

- [ ] `git status` 가 깨끗하다. (`nothing to commit` 또는 비슷한 문장)
- [ ] 실험 커밋과 되돌리기 커밋이 모두 기록에 있다. (지우지 않았다)

---

## 3. 확인하기
- [ ] 범위 밖 변경을 검증이 통과시켰다는 것을 직접 봤다.
- [ ] 저장 전 변경을 `git restore` 로 되돌렸다.
- [ ] 저장 후 변경을 `git revert` 로 되돌렸고, 기록이 남아 있는 것을 봤다.
- [ ] 4단계 표를 채웠다.

## 4. 자주 만나는 오류

| 증상 | 해결 |
|---|---|
| `git revert` 가 편집기를 연다 | `--no-edit` 를 빠뜨렸다. 편집기를 닫으려면 `Esc` 를 누르고 `:q!` 를 친다. (VS Code 면 저장하고 닫는다) |
| `git revert` 가 충돌을 알린다 | 되돌릴 커밋 이후에 같은 줄을 또 고쳤다. `git revert --abort` 로 취소하고 `git log` 로 순서를 확인한다. |
| `git restore` 후에도 파일이 남아 있다 | 새로 만들어진 파일이다. `git status` 에서 찾아 직접 지운다. |
| 되돌렸는데 검증이 실패한다 | 되돌리기 전 다른 변경이 섞여 있었을 수 있다. `git log` 와 `git diff` 로 확인한다. |

## 5. 확인 문제
1. "검증 통과"와 "범위 안에 있다"의 차이를 한 문장으로 쓰시오.
2. `git restore` 와 `git revert` 의 차이를 "기록"이라는 낱말로 설명하시오.
3. `git reset --hard` 를 쓰면 안 되는 이유는 무엇인가?
4. 되돌린 뒤에도 `python verify.py` 를 다시 해야 하는 이유는 무엇인가?
