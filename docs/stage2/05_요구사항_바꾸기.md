# 2단계 5장. 요구사항이 바뀌었을 때

> **실행 환경: 도커.** 명령 블록은 컨테이너 안(bash)에서 칩니다. `[Windows]` 로 표시된 블록만 Windows PowerShell 에서 칩니다. 파일 편집은 Windows 의 VS Code 에서 합니다. 자세한 설명은 [도커로 실행하기](../docker/00_도커로_실행하기.md)를 봅니다.

| | |
|---|---|
| 시간 | 2시간 |
| 준비물 | 4장까지 완료. 템플릿 `/tutorial/templates/stage2/CHANGE_요청서.md`, `/tutorial/templates/stage2/tests/test_lending_v2.py` |
| 결과 | 변경 요청서를 칸 채우기로 쓰고, 기준(테스트)은 사람이 바꾼 뒤 AI 에게 구현시킨다 |

## 이 장에서 할 일 한눈에 보기

1. 변경 전 상태를 확인한다. (10분)
2. 변경 요청서를 칸별로 채운다. (25분)
3. 영향 받는 테스트를 찾는다. (10분)
4. 승인하고, 기준을 사람이 바꾼다. (20분)
5. 바뀐 기준으로 빨강을 확인한다. (10분)
6. AI 에게 구현시키고 대조한다. (30분)
7. 저장한다. (15분)

## 1단계. 변경 전 상태 확인하기 (10분)

**[컨테이너]**

```bash
cd /workspace/library
python verify.py
git status
```

확인 기준: "검증 통과"가 나오고, `git status` 에 바뀐 파일이 없어야 합니다("nothing to commit" 또는 `books.json` 만 무시됨). 이 상태가 **변경 전 기준점**입니다.

## 2단계. 변경 요청서 칸별로 채우기 (25분)

**[컨테이너]**

```bash
cd /workspace/library
cp /tutorial/templates/stage2/CHANGE_요청서.md .
```

**[Windows]** VS Code 에서 `C:\harness-lab\library\CHANGE_요청서.md` 를 엽니다. 아래 표의 칸을 채웁니다. 칸마다 **그대로 쓸 문장**이 있는 곳은 그 문장을 쓰고, 빈칸은 내 말로 씁니다.

| 요청서의 칸 | 어떻게 채우나 |
|---|---|
| 1. 요구사항 번호 | `- 요구사항 번호: R3, R4` 는 그대로 둔다 |
| 1. 무엇이 바뀌나 | `- 무엇이 바뀌나: 대출하면 loan_days 칸에 14 가 함께 기록된다. 반납하면 그 칸을 지운다.` 로 바꾼다 |
| 1. 왜 바꾸나 | `- 왜 바꾸나: [빈칸]` 을 "도서관에서 대출 기간을 알아야 하기 때문이다" 또는 내 말로 한 문장 쓴다 |
| 2. 영향을 받는 테스트 | 아래 3단계에서 찾은 테스트 이름을 적는다 |
| 3. 테스트 기준을 어떻게 바꾸나 | 그대로 둔다 (아래 4단계에서 사람이 한다) |
| 4. 승인 | 승인 날짜와 이름은 4단계 뒤에 적는다 |

확인 기준: 요청서에 `[` 가 남아 있지 않아야 합니다. 컨테이너에서 `grep -c "\[" CHANGE_요청서.md` 를 치면 `0` 입니다. (4번 승인 줄의 빈칸은 `______` 밑줄이라서 대괄호가 없어도 됩니다.)

## 3단계. 영향을 받는 테스트 찾기 (10분)

**[컨테이너]**

```bash
cd /workspace/library
grep -n "assert book ==" tests/test_lending.py
```

확인 기준: 책 모양 전체를 `==` 로 비교하는 줄이 나옵니다. 그 줄이 속한 **테스트 함수 이름**을 찾아 요청서 2번 칸에 적습니다.

```bash
grep -n "^def test_" tests/test_lending.py
```

줄 번호가 가장 가까운 `def test_` 줄이 함수 이름입니다.

확인 질문:
- [ ] 이 변경으로 책 모양이 달라지는 테스트를 찾았다.
- [ ] 책 상태만 확인하는 테스트(예: status 만 보는 것)는 적지 않았다.

## 4단계. 승인하고 테스트 기준을 사람이 바꾸기 (20분)

이 단계는 **사람이** 합니다. AI 에게 맡기지 않습니다.

**(1) 승인:** 요청서 4번에 승인 날짜와 이름을 적습니다.

**(2) 새 기준을 옆에 두기:**

**[컨테이너]**

```bash
cd /workspace/library
cp /tutorial/templates/stage2/tests/test_lending_v2.py tests/test_lending_v2.py
ls tests
```

**(3) 4장에서 내가 추가한 테스트를 옮기기:** 4장에서 `test_lending.py` 맨 아래에 붙인 `test_return_clears_borrower` 함수는 새 기준에 없습니다. 그래서 옮깁니다.

**[Windows]** VS Code 에서 `tests\test_lending.py` 를 열어 `def test_return_clears_borrower():` 부터 파일 끝까지를 복사합니다. 그다음 `tests\test_lending_v2.py` 맨 아래에 빈 줄 두 개를 두고 붙여 넣고 저장합니다.

**(4) 새 기준으로 바꾸기:**

**[컨테이너]**

```bash
cd /workspace/library
mv tests/test_lending_v2.py tests/test_lending.py
ls tests
```

확인 기준: `tests` 폴더에 `test_books.py` 와 `test_lending.py` 가 있고, `test_lending_v2.py` 는 없어야 합니다.

## 5단계. 바뀐 기준으로 빨강 확인하기 (10분)

**[컨테이너]**

```bash
cd /workspace/library
python -m pytest tests/test_lending.py
```

확인 기준:
- 실패가 **하나 이상** 나옵니다. 실패한 테스트 이름을 옮겨 적습니다.

```text
(실패한 테스트 이름과 FAILED 줄)
```

- 실패한 테스트는 대출(`lend`)과 관련된 것이어야 합니다. 반납 테스트만 실패하면 4장의 반납 수정을 다시 확인합니다.

> 실패는 정상입니다. 기준이 바뀌었으니 구현이 아직 따라오지 않은 것입니다. 실패를 보고 "구현이 틀렸다"고 바로 결론 내리지 않습니다.

## 6단계. AI 에게 구현시키고 대조하기 (30분)

**[컨테이너]**

```bash
cd /workspace/library
opencode
```

**[AI]**

```text
CHANGE_요청서.md 의 변경을 구현해 줘. tests/ 는 이미 새 기준으로 바뀌어 있으니 고치지 마.
계획을 먼저 말하고, 내가 "진행"이라고 하면 library.py 만 고쳐 줘.
```

계획을 아래 세 질문으로 검토합니다.

| 질문 | 답 (예/아니오) | 아니오면 입력할 문장 |
|---|---|---|
| 1. 고치는 파일이 library.py 한 개뿐인가? | | 아래 문장 A |
| 2. 대출할 때 loan_days 를 14 로 넣고, 반납할 때 지운다고 했는가? | | 아래 문장 A |
| 3. tests/ 를 고친다는 말이 없는가? | | 아래 문장 A |

**[AI] 문장 A** (아니오일 때, 번호만 바꿔 입력합니다)

```text
계획 [번호]번이 CHANGE_요청서.md 와 맞지 않아. 그 부분을 고쳐서 계획을 다시 말해 줘. 아직 파일은 고치지 마.
```

모두 예이면 입력합니다.

**[AI]**

```text
진행
```

끝나면 `/exit` 를 칩니다. 대조합니다.

**[컨테이너]**

```bash
cd /workspace/library
python -m pytest tests/test_books.py tests/test_lending.py
diff tests/test_lending.py /tutorial/templates/stage2/tests/test_lending_v2.py
```

확인 기준:

| 확인할 것 | 기대하는 결과 | 실제 결과 (예/아니오) |
|---|---|---|
| 테스트 결과 | 모두 통과한다 (`13 passed`) | |
| diff 출력 | 원본 2차 기준과 다른 줄이 **4장에서 옮긴 테스트 블록 뿐**이다 (`>` 로 시작하는 줄만 보인다) | |

diff 에서 `<` 로 시작하는 줄(기준에서 바뀐 줄)이 있으면 AI 가 테스트를 고친 것입니다. 되돌리게 합니다.

## 7단계. 저장하기 (15분)

**[컨테이너]**

```bash
cd /workspace/library
python verify.py
git add -A
git status
git commit -m "5장: 대출 기간 14일 기록 (요구사항 변경 승인됨, 기준은 사람이 변경, R3·R4)"
git log --oneline
```

확인 기준: 커밋 메시지에 "요구사항 변경 승인됨"이 들어가야 합니다. `git status` 에 `CHANGE_요청서.md` 가 보여도 함께 저장합니다.

## 확인 체크리스트
- [ ] 변경 전 `python verify.py` 가 "검증 통과"였다.
- [ ] 요청서 1~2번 칸을 채웠고, 대괄호가 남지 않았다.
- [ ] 영향 받는 테스트 이름을 찾아 적었다.
- [ ] 승인 날짜와 이름을 적었다.
- [ ] 4장 테스트 블록을 새 기준에 옮겼다.
- [ ] 바뀐 기준으로 실패를 확인했다.
- [ ] 계획 검토 세 질문에 답했고, `diff` 결과를 확인했다.
- [ ] 커밋 메시지에 승인 여부가 들어 있다.

## 자주 만나는 오류

| 증상 | 해결 |
|---|---|
| `mv` 후에도 `test_lending_v2.py` 가 남아 있다 | `ls tests` 로 확인한다. `mv` 가 실패했다면 파일 이름을 다시 쓴다. |
| 4장 테스트 블록을 옮기지 않았다 | 기준 교체 후 `test_return_clears_borrower` 가 사라진다. 4단계 (3)을 다시 한다. |
| AI 가 `tests/test_lending.py` 를 고쳐서 통과시켰다 | `diff` 의 `<` 줄을 찾는다. AI 에게 "tests 를 원래대로 되돌리고 library.py 만 고쳐 줘"라고 말한다. |
| 실패가 반납 테스트에서만 난다 | 4장의 반납 수정(`borrower` 지우기)이 남아 있는지 `grep -n "borrower" library.py` 로 확인한다. |
