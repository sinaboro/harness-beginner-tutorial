# 2단계 4장. AI 가 만든 실수 찾기

> **실행 환경: 도커.** 명령은 컨테이너 안(bash)에서 칩니다. 교안의 PowerShell 명령은 [도커로 실행하기](../docker/00_도커로_실행하기.md)의 명령 대응표(4절)를 보고 바꿔 씁니다. 편집은 Windows 의 VS Code 에서 합니다.

| | |
|---|---|
| 시간 | 2시간 |
| 준비물 | 3장까지 완료 (또는 `examples/stage2/library_bugged.py` 를 사용) |
| 결과 | AI 가 만든 초안의 실수를 테스트로 잡고, 테스트가 못 잡는 실수를 사람이 찾아 테스트를 추가한다 |

## 학습 목표
1. 테스트가 잡는 실수와 못 잡는 실수가 있다는 것을 안다.
2. 실패 출력을 읽어 어떤 약속이 깨졌는지 찾는다.
3. 테스트에 빠진 약속을 사람이 직접 추가한다.

---

## 1. 개념 — 테스트는 약속만 확인한다

테스트는 **적힌 약속만** 확인합니다. 약속에 없는 실수는 테스트가 통과해도 남아 있습니다.

| 종류 | 예 | 누가 찾나 |
|---|---|---|
| 약속이 있고, 지켜지지 않음 | 이미 대출 중인 책을 또 빌릴 수 있다 | 테스트가 실패로 알려 준다 |
| 약속이 없음 | 반납해도 빌린 사람 이름이 남는다 | 사람이 직접 보고 찾는다 |

> 이 장의 목표는 "테스트가 통과했으니 됐다"가 틀린 이유를 직접 보는 것입니다.

## 2. 따라 하기

### 1단계. 초안 가져오기 (10분)

이 장에서는 AI 가 만든 것처럼 준비된 초안을 씁니다. (3장까지 직접 만든 `library.py` 는 잠시 보관합니다.)

**[PS]**

```powershell
cd C:\harness-lab\library
Copy-Item library.py library_mine.py
Copy-Item C:\harness-beginner-tutorial\examples\stage2\library_bugged.py library.py
dir
```

> `library_mine.py` 는 나중에 비교용으로 씁니다. 이 장이 끝나면 되돌립니다.

**[PS]**

### 3단계. 실패 출력 읽기 (20분)

실패한 테스트 두 개의 이름과 `assert` 줄을 읽습니다.

| 실패한 테스트 | 깨진 약속 (테스트가 말하는 것) | 원인으로 짐작되는 줄 |
|---|---|---|
| | | |
| | | |

> 테스트 이름이 바로 약속입니다. `test_lend_lent_book_raises` 는 "이미 대출 중인 책은 빌릴 수 없다"입니다.

### 4단계. AI 에게 고치게 하기 (25분)

**[PS]**

```powershell
opencode
```

**[AI]**

```text
python -m pytest 를 실행하면 두 테스트가 실패해. 실패한 테스트 이름과 아래 출력을 보고, 원인을 먼저 설명해 줘.
(실패 출력을 붙여 넣는다)
내가 "진행"이라고 하면 library.py 만 고쳐 줘. tests/ 는 건드리지 마.
```

계획을 검토하고 `진행` 이라고 답합니다. 끝나면 `/exit`.

**[PS]**

```powershell
python -m pytest tests\test_books.py tests\test_lending.py
```

이제 통과해야 합니다. 여기서 "끝났다"고 생각하면 안 됩니다.

### 5단계. 테스트가 못 잡은 실수 찾기 (25분)

테스트가 모두 통과한 상태에서, 대출과 반납을 한 번 해 봅니다.

**[PS]**

```powershell
python -c "from library import *; b=[]; add_book(b,'데미안','헤세'); lend_book(b,1,'철수'); print(return_book(b,1))"
```

결과를 읽습니다.

```text
{'id': 1, ..., 'status': 'available', 'borrower': '철수'}
```

**반납했는데 빌린 사람 이름(`borrower`)이 남아 있습니다.** 1장의 요구사항 R4 에는 "borrower 를 None 으로 바꾼다"가 적혀 있습니다. 그런데 테스트에는 이 약속이 없습니다. 테스트는 `status` 만 확인하기 때문입니다.

이것이 **테스트가 못 잡은 실수**입니다.

### 6단계. 빠진 약속을 사람이 추가하기 (20분)

이번에는 **사람이** 테스트를 씁니다. AI 에게 맡기지 않습니다.

**[PS]**

```powershell
notepad tests\test_lending.py
```

파일 맨 아래에 다음을 추가하고 저장합니다.

```python


def test_return_clears_borrower():
    # 반납하면 빌린 사람 이름을 지운다. (요구사항 R4)
    books = make_books()
    lend_book(books, 1, "철수")
    book = return_book(books, 1)
    assert book["borrower"] is None
```

테스트를 실행합니다.

**[PS]**

```powershell
python -m pytest tests\test_lending.py::test_return_clears_borrower
```

실패해야 합니다(빨강). 이것이 새로 찾은 실수를 잡는 약속입니다.

### 7단계. AI 에게 고치게 하기 (20분)

**[AI]**

```text
tests/test_lending.py 의 test_return_clears_borrower 가 실패해. 반납할 때 borrower 를 None 으로 바꾸는 줄을 library.py 의 return_book 에 추가해 줘. 계획을 먼저 말하고 승인을 기다려. tests/ 는 고치지 마.
```

`진행` 이라고 답하고, 끝나면 확인합니다.

**[PS]**

```powershell
python verify.py
```

"검증 통과"가 나오면 실수가 고쳐진 것입니다.

### 8단계. 비교하고 저장하기 (15분)

3장에서 직접 만든 `library_mine.py` 와 지금 고친 `library.py` 의 `return_book` 을 비교합니다.

**[PS]**

```powershell
notepad library_mine.py
notepad library.py
```

두 파일의 `return_book` 에서 차이를 한 가지 적습니다. 차이를 적은 뒤 비교용 파일은 지웁니다.

**[PS]**

```powershell
Remove-Item library_mine.py
python verify.py
git add -A
git status
git commit -m "4장: 테스트가 못 잡은 반납 실수를 테스트로 추가 (R4)"
```

> `library_mine.py` 는 저장소에 올리지 않습니다. 지운 뒤 커밋하는 이유입니다.

## 3. 확인하기
- [ ] 실패 두 개를 보고, 깨진 약속의 이름을 말할 수 있다.
- [ ] 테스트가 통과한 뒤에도 실수가 남아 있는 것을 직접 봤다.
- [ ] 빠진 약속을 사람이 테스트로 추가했다.
- [ ] `tests/` 안의 기존 테스트는 바뀌지 않았다.

## 4. 자주 만나는 오류

| 증상 | 해결 |
|---|---|
| 실패가 두 개가 아니다 | 초안을 바꿨는지 확인한다. `Copy-Item` 을 다시 실행한다. |
| AI 가 테스트를 고쳐서 통과시켰다 | 권한이 막아야 한다. 막히지 않았다면 `Compare-Object` 로 확인하고 원래대로 되돌린다. |
| 새 테스트를 추가했는데 실패하지 않는다 | 그 테스트가 확인하는 줄을 다시 본다. `make_books()` 와 `lend_book` 호출 순서를 확인한다. |
