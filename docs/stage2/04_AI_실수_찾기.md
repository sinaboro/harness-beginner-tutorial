# 2단계 4장. AI 가 만든 실수 찾기

> **실행 환경: 도커.** 명령 블록은 컨테이너 안(bash)에서 칩니다. `[Windows]` 로 표시된 블록만 Windows PowerShell 에서 칩니다. 파일 편집은 Windows 의 VS Code 에서 합니다. 자세한 설명은 [도커로 실행하기](../docker/00_도커로_실행하기.md)를 봅니다.

| | |
|---|---|
| 시간 | 2시간 |
| 준비물 | 3장을 마친 상태 (`library.py` 가 커밋되어 있다) |
| 결과 | AI 가 만든 초안의 실수를 테스트로 잡고, 테스트가 못 잡는 실수를 직접 찾아 테스트를 추가한다 |

## 이 장에서 할 일 한눈에 보기

1. 내 완성본을 옆에 보관하고, AI 초안(실수 있음)으로 바꾼다. (10분)
2. 테스트로 실수를 찾는다. (15분)
3. AI 에게 고치게 한다. (20분)
4. 테스트가 못 잡는 실수를 직접 찾는다. (20분)
5. 빠진 테스트를 사람이 쓰고, AI 가 고치게 한다. (25분)
6. 비교하고 저장한다. (15분)

---

## 1단계. 내 완성본 보관하고 초안으로 바꾸기 (10분)

**[컨테이너]**

```bash
cd /workspace/library
cp library.py library_mine.py
cp /tutorial/examples/stage2/library_bugged.py library.py
ls
```

확인 기준: `library_mine.py` 와 `library.py` 가 모두 보입니다. `library.py` 는 AI 가 만든 것처럼 준비된 초안입니다.

> `library_mine.py` 는 6단계에서 비교한 뒤 지웁니다.

## 2단계. 테스트로 실수 찾기 (15분)

**[컨테이너]**

```bash
cd /workspace/library
python -m pytest tests/test_books.py tests/test_lending.py
```

출력의 마지막 줄을 보고 아래 표를 채웁니다. 실패 줄은 `FAILED` 로 시작합니다.

| 실패한 테스트 이름 (그대로 옮긴다) | 이 테스트가 말하는 약속 (한 문장. 테스트 함수 이름과 `assert` 줄을 보고 쓴다) |
|---|---|
| | |
| | |

확인 기준: 실패가 **두 개**여야 합니다. (`2 failed, 11 passed`) 다른 개수라면 1단계를 다시 합니다.

## 3단계. AI 에게 고치게 하기 (20분)

**[컨테이너]**

```bash
cd /workspace/library
opencode
```

**[AI]**

```text
python -m pytest tests/test_books.py tests/test_lending.py 를 실행하면 실패 두 개가 나와. 실패한 테스트 이름과 아래 출력을 보고, 원인을 먼저 설명해 줘.
(실패 출력의 마지막 15줄을 붙여 넣는다)
내가 "진행"이라고 하면 library.py 만 고쳐 줘. tests/ 는 건드리지 마.
```

AI 의 원인 설명을 읽고 아래 두 질문에 답합니다.

| 질문 | 답 (예/아니오) |
|---|---|
| 1. 설명한 원인이 2단계 표의 "약속"과 같은 내용인가? | |
| 2. 계획에 tests/ 를 고친다는 말이 없는가? | |

모두 예이면 입력합니다.

**[AI]**

```text
진행
```

끝나면 `/exit` 를 칩니다. 다시 확인합니다.

**[컨테이너]**

```bash
cd /workspace/library
python -m pytest tests/test_books.py tests/test_lending.py
```

확인 기준: `13 passed` 가 나와야 합니다. 이 시점에 테스트는 모두 통과하지만, 실수가 아직 하나 남아 있습니다.

## 4단계. 테스트가 못 잡은 실수 직접 찾기 (20분)

테스트가 모두 통과한 뒤에도 실수가 남았는지 직접 확인합니다.

**[컨테이너]**

```bash
cd /workspace/library
python -c "
from library import add_book, lend_book, return_book
books = []
add_book(books, '데미안', '헤세')
lend_book(books, 1, '철수')
print('반납 전:', books[0])
print('반납 후:', return_book(books, 1))
"
```

확인 기준: 반납 후 출력에서 `'status'` 와 `'borrower'` 를 찾아 옮깁니다.

| 확인할 것 | 실제 값 (출력에서 옮긴다) | 약속대로인가? (예/아니오) |
|---|---|---|
| 반납 후 `status` | | |
| 반납 후 `borrower` | | |

약속: 반납하면 빌린 사람 이름(`borrower`)이 `None` 이 되어야 합니다. (REQUIREMENTS 의 R4 와 같습니다.)

`borrower` 가 `None` 이 아니면 **테스트가 못 잡은 실수**입니다. 3장의 테스트는 `status` 만 확인했기 때문입니다.

## 5단계. 빠진 테스트를 사람이 쓰고, AI 에게 고치게 하기 (25분)

**무엇을:** 테스트 파일에 약속을 한 줄 더합니다. **이것은 사람이 씁니다.** AI 에게 맡기지 않습니다.

**[Windows]** VS Code 에서 `C:\harness-lab\library\tests\test_lending.py` 를 엽니다. 파일 맨 아래에 아래 블록을 **그대로** 붙여 넣고 저장합니다. 앞에 빈 줄 두 개를 둡니다.

```python


def test_return_clears_borrower():
    # 반납하면 빌린 사람 이름을 지운다. (요구사항 R4)
    books = []
    add_book(books, "데미안", "헤세")
    lend_book(books, 1, "철수")
    book = return_book(books, 1)
    assert book["borrower"] is None
```

**[컨테이너]**

```bash
cd /workspace/library
python -m pytest tests/test_lending.py::test_return_clears_borrower
```

확인 기준: **실패해야 합니다.** (빨강) 실패하지 않으면 블록을 다시 읽고, 파일 맨 아래에 붙었는지 확인합니다.

그다음 AI 에게 고치게 합니다.

**[AI]**

```text
tests/test_lending.py 의 test_return_clears_borrower 가 실패해. 반납할 때 borrower 를 None 으로 바꾸도록 library.py 의 return_book 을 고쳐 줘. 계획을 먼저 말하고 내가 "진행"이라고 하면 library.py 만 고쳐. tests/ 는 건드리지 마.
```

계획을 확인하고 `진행` 을 입력합니다. 끝나면 `/exit` 를 칩니다.

**[컨테이너]**

```bash
cd /workspace/library
python verify.py
```

확인 기준: "검증 통과"가 나와야 합니다. (초록)

## 6단계. 내 완성본과 비교하고 저장하기 (15분)

**[컨테이너]**

```bash
cd /workspace/library
diff library_mine.py library.py
```

확인 기준: 차이가 나는 줄을 두 개 이상 찾아 적습니다. 특히 `return_book` 함수의 차이를 한 문장으로 적습니다.

```text
return_book 의 차이: (여기에 한 문장)
```

비교가 끝나면 `library_mine.py` 를 지우고 저장합니다.

**[컨테이너]**

```bash
cd /workspace/library
rm -f library_mine.py
python verify.py
git add -A
git status
git commit -m "4장: 테스트가 못 잡은 반납 실수를 테스트로 추가하고 고침 (R4)"
git log --oneline
```

확인 기준: 커밋이 한 줄 생기고, `git status` 에 `library_mine.py` 가 없어야 합니다.

## 확인 체크리스트
- [ ] 실패가 두 개였고, 각 실패의 약속을 한 문장으로 적었다.
- [ ] 테스트가 모두 통과한 뒤에도 borrower 가 남는 것을 직접 봤다.
- [ ] 빠진 테스트를 사람이 쓰고, 실패하는 것을 확인했다.
- [ ] AI 가 `library.py` 만 고쳤고, `verify.py` 가 통과한다.
- [ ] 차이를 한 문장으로 적었고, 비교용 파일을 지웠다.

## 자주 만나는 오류

| 증상 | 해결 |
|---|---|
| 실패가 두 개가 아니다 | `cp /tutorial/examples/stage2/library_bugged.py library.py` 를 다시 친다. |
| 새 테스트가 처음부터 통과한다 | 붙여 넣은 함수 이름이 `test_` 로 시작하는지 본다. 블록이 파일 맨 아래에 있는지 본다. |
| AI 가 테스트를 고쳐서 통과시켰다 | `diff tests/test_lending.py /tutorial/templates/stage2/tests/test_lending.py` 로 확인한다. 5단계에서 추가한 테스트 때문에 달라진 것은 정상이다. 그 밖의 줄이 다르면 AI 에게 되돌리게 한다. |
| `library_mine.py` 를 지우는 것을 잊었다 | `rm -f library_mine.py` 를 친 뒤 커밋한다. |
