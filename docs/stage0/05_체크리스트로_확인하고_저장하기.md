# 0단계 5장. 체크리스트로 확인하고 저장하기

> **실행 환경: 도커.** 명령 블록은 컨테이너 안(bash)에서 칩니다. `[Windows]` 로 표시된 블록만 Windows PowerShell 에서 칩니다. 파일 편집은 Windows 의 VS Code 에서 합니다. 자세한 설명은 [도커로 실행하기](../docker/00_도커로_실행하기.md)를 봅니다.

| | |
|---|---|
| 시간 | 1시간 30분 |
| 준비물 | 4장의 `/workspace/card4` 폴더 |
| 결과 | AI 의 말이 아니라 체크리스트로 "다 됐다"를 판단하고, 체크가 끝난 뒤에만 저장한다 |

## 학습 목표
1. AI 의 "완료했습니다"를 그대로 믿으면 안 되는 이유를 말한다.
2. 체크리스트를 사람이 직접 확인하는 방법을 익힌다.
3. 체크가 끝난 것만 저장한다.

---

## 1. 개념 — 말과 확인은 다르다

AI 는 "완료했습니다"라고 말할 수 있습니다. 하지만 그 말이 맞는지는 **사람이 확인**해야 합니다. 체크리스트는 그 확인을 빠뜨리지 않게 해 주는 목록입니다.

| 확인하는 방법 | 예 | 한계 |
|---|---|---|
| AI 의 보고를 읽는다 | "모든 기능을 구현했습니다" | 맞는지 알 수 없다 |
| 체크리스트를 직접 본다 | "좁은 화면에서 글이 잘리지 않는다" | 내가 직접 눈으로 봐야 한다 |

> 체크리스트의 한 줄은 **내가 직접 보고 확인할 수 있는 것**이어야 합니다.

---

## 2. 따라 하기

### 1단계. AI 에게 명함 만들기 (30분)

**[컨테이너]**

```bash
cd /workspace/card4
opencode
```

**[AI]**

```text
TASK_명함.md 를 읽고 그 지시대로 작업해 줘. 먼저 계획만 말하고 내 승인을 기다려. 계획에 동의하면 "진행"이라고 할게.
```

> `TASK_명함.md` 는 `templates/stage0` 에 있습니다. 이 폴더로 복사한 뒤 쓰거나, 3장의 지시서를 붙여 넣습니다.

계획을 확인하고 `진행` 이라고 답합니다. 끝나면 `/exit` 로 나옵니다.

### 2단계. 파일 확인하기 (5분)

**[컨테이너]**

```bash
ls -la
git status
```

- [ ] 파일이 `index.html`, `style.css` 두 개뿐이다. (CHECKLIST.md 등 다른 파일이 바뀌지 않았다)

### 3단계. 체크리스트 1~2단계 (10분)

`CHECKLIST.md` 를 열고 1단계, 2단계 항목을 확인합니다. 브라우저에서 `index.html` 을 더블클릭해 엽니다.

**[Windows]**

```bash
# (Windows) CHECKLIST.md 을(를) VS Code 로 열어 고칩니다
# (Windows) index.html 을(를) 탐색기에서 더블클릭합니다
```

확인한 항목에만 `[x]` 를 표시합니다. 확인하지 않았는데 체크하면 안 됩니다.

### 4단계. 체크리스트 3~4단계 (15분)

브라우저 창에서 내용을 확인합니다.

- 취미 목록이 세 개 세로로 보이는지
- 이메일 링크를 눌렀을 때 작성 창이 열리는지
- 창의 폭을 좁혔을 때 글이 잘리지 않는지

**창 폭 줄이기:** 브라우저 창의 오른쪽 모서리를 잡고 천천히 왼쪽으로 줄입니다. 가로 스크롤바가 생기면 실패입니다.

확인한 항목을 체크합니다.

### 5단계. 실패한 항목을 고치게 하기 (20분)

체크되지 않은 항목이 있다면, 어떤 항목이 안 되는지 AI 에게 말합니다. 체크리스트 자체를 고치라고 하면 안 됩니다.

**[AI]**

```text
CHECKLIST.md 의 3단계 두 번째 항목이 안 돼. 창을 좁히면 이메일 링크가 화면 밖으로 나가. 원인을 먼저 설명하고, 내가 "진행"이라고 하면 style.css 만 고쳐 줘. CHECKLIST.md 는 고치지 마.
```

고친 뒤 4단계로 돌아가 다시 확인합니다.

### 6단계. 저장하기 (10분)

모든 항목에 체크가 끝나면 저장합니다. 저장은 **사람이** 합니다.

**[컨테이너]**

```bash
git add -A
git status
git commit -m "5장: 명함 페이지 완성 (체크리스트 확인 완료)"
git log --oneline
```

커밋 기록이 한 줄 생기면 끝입니다.

> `git status` 에서 **체크하지 않은 항목이 있는데** 저장하고 싶어진다면, 저장하지 말고 5단계로 돌아갑니다.

---

## 3. 확인하기
- [ ] 체크리스트의 모든 항목을 직접 확인했다.
- [ ] 실패한 항목이 있었다면, AI 에게 원인부터 설명하게 했다.
- [ ] 커밋 기록이 한 줄 생겼다.

## 4. 자주 만나는 오류

| 증상 | 해결 |
|---|---|
| `start index.html` 이 열리지 않는다 | 파일 이름과 확장자를 확인한다. VS Code 로 열어 `.html` 인지 본다. |
| `git commit` 이 `Please tell me who you are` | 00 준비하기 6번의 `git config --global` 두 줄을 다시 실행한다. |
| AI 가 CHECKLIST.md 를 고친다 | 4장의 권한 설정을 확인한다. 원래 내용을 `templates/stage0/CHECKLIST.md` 와 비교해서 AI 에게 원래대로 되돌리게 한다. |

## 5. 확인 문제
1. AI 가 "완료했습니다"라고 말했을 때 사람이 확인해야 하는 이유는 무엇인가?
2. 체크리스트의 한 줄이 "예쁘게 보인다"이면 왜 좋지 않은가?
3. 저장을 사람이 하는 이유는 무엇인가?
