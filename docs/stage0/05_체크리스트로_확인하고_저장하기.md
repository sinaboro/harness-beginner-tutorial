# 0단계 5장. 체크리스트로 확인하고 저장하기

> **실행 환경: 도커.** 명령 블록은 컨테이너 안(bash)에서 칩니다. `[Windows]` 로 표시된 블록만 Windows PowerShell 에서 칩니다. 파일 편집은 Windows 의 VS Code 에서 합니다. 자세한 설명은 [도커로 실행하기](../docker/00_도커로_실행하기.md)를 봅니다.

| | |
|---|---|
| 시간 | 1시간 30분 |
| 준비물 | 4장의 `/workspace/card4` 폴더 |
| 결과 | AI 가 만든 파일을 체크리스트 항목마다 직접 확인하고, 확인 기록을 남긴 뒤에만 저장한다 |

## 이 장에서 할 일 한눈에 보기

1. AI 에게 지시서를 건네고 파일을 만들게 한다. (25분)
2. 체크리스트를 `확인기록.md` 로 복사한다. (5분)
3. 항목 ①~④ 를 확인하고 표에 기록한다. (15분)
4. 항목 ⑤~⑦ 을 확인하고 기록한다. (10분)
5. 항목 ⑧~⑭ 를 확인하고 기록한다. (25분)
6. 실패한 항목을 AI 에게 번호로 알려 고치게 한다. (15분)
7. 항목 ⑮~⑯ 을 확인하고 저장한다. (15분)

> **중요한 규칙:** `CHECKLIST.md` 원본에는 체크 표시를 하지 않습니다. 확인 기록은 **`확인기록.md`** 에만 씁니다.

---

## 1단계. AI 에게 명함 만들게 하기 (25분)

**[컨테이너]**

```bash
cd /workspace/card4
cp /tutorial/templates/stage0/TASK_명함.md .
ls -la
```

`TASK_명함.md` 가 보이면 됩니다. OpenCode 를 엽니다.

**[컨테이너]**

```bash
opencode
```

OpenCode 입력 칸에 아래 문장을 **그대로** 입력합니다.

**[AI]**

```text
TASK_명함.md 를 읽고 그 지시대로 작업해 줘. 먼저 계획만 말하고, 내가 "진행"이라고 할 때까지 파일을 만들지 마.
```

AI 가 계획을 말하면 4장 3단계의 검토 방식으로 확인합니다.
- 계획이 `index.html`, `style.css` 두 개만 만든다고 하는가? (예/아니오)
- 계획에 CHECKLIST.md 를 고친다는 말이 없는가? (예/아니오)

모두 예이면 아래를 입력합니다. 아니오이면 아니오 내용을 말한 뒤 다시 계획을 받습니다.

**[AI]**

```text
진행
```

AI 가 끝나면 `/exit` 를 칩니다.

## 2단계. 확인기록 파일 만들기 (5분)

**[컨테이너]**

```bash
cd /workspace/card4
cp CHECKLIST.md 확인기록.md
ls -la
```

이제 `확인기록.md` 에 체크 표시를 합니다. 원본 `CHECKLIST.md` 는 열어 보기만 합니다.

> **번호 세는 법:** `확인기록.md` 에는 번호가 없습니다. `- [ ]` 로 시작하는 줄을 **위에서부터** 셉니다. 첫 번째 줄이 ①, 두 번째가 ②, 열여섯 번째가 ⑯입니다. 제목 줄(`## …`)은 세지 않습니다.

**[Windows]** VS Code 에서 `C:\harness-lab\card4\확인기록.md` 를 엽니다.

## 3단계. 확인기록의 항목 ①~④ 확인하기 (15분)

**무엇을:** `확인기록.md` 에서 **1단계와 2단계** 항목 네 개(①~④)를 확인합니다. 항목 번호는 `확인기록.md` 에서 위에서부터 붙인 순서입니다.

**[컨테이너]**

```bash
cd /workspace/card4
ls -la
```

**[Windows]** `C:\harness-lab\card4\index.html` 을 **더블클릭**해서 브라우저로 엽니다.

| 번호 | 확인기록.md 의 문장 (그대로) | 어떻게 확인하나 | 맞으면 `[x]` |
|---|---|---|---|
| ① | 폴더에 `index.html` 과 `style.css` 두 파일만 있다. | `ls -la` 결과에 파일이 두 개인지 본다 | |
| ② | 두 파일을 메모장으로 열어도 글자가 깨져 보이지 않는다. | VS Code 에서 두 파일을 열어 한글을 본다 | |
| ③ | `index.html` 을 더블클릭했을 때 브라우저에서 열린다. | 브라우저 창이 열리는지 본다 | |
| ④ | 페이지 맨 위에 이름이 가장 크게 보인다. (R1) | 눈으로 본다. 이름 글씨가 가장 큰가 | |

`[x]` 는 `확인기록.md` 에서 `- [ ]` 를 `- [x]` 로 바꿔서 표시합니다. **맞을 때만 바꿉니다.**

## 4단계. 확인기록의 항목 ⑤~⑦ 확인하기 (10분)

**무엇을:** `확인기록.md` 에서 **2단계 나머지와 3단계** 항목 세 개(⑤~⑦)를 확인합니다.

| 번호 | 확인기록.md 의 문장 (그대로) | 어떻게 확인하나 | 맞으면 `[x]` |
|---|---|---|---|
| ⑤ | 이름 아래에 한 줄 소개가 보인다. (R1) | 눈으로 본다 | |
| ⑥ | "취미" 제목 아래에 취미가 세 개 세로로 나열된다. (R2) | 브라우저에서 취미 줄을 센다 (세 줄이어야 한다) | |
| ⑦ | "이메일 보내기" 링크를 누르면 이메일 작성 창이 열린다. (R3) | 링크를 한 번 누른다 | |

## 5단계. 확인기록의 항목 ⑧~⑭ 확인하기 (25분)

**무엇을:** 나머지 항목을 확인합니다.

| 번호 | 확인기록.md 의 문장 (그대로) | 어떻게 확인하나 | 맞으면 `[x]` |
|---|---|---|---|
| ⑧ | 바탕은 연한 색, 이름은 진한 남색이다. (R5) | 눈으로 본다 | |
| ⑨ | 브라우저 창을 가장 좁게 줄여도 글이 가로로 잘리지 않는다. (R4) | 창의 오른쪽 끝을 잡고 가장 좁게 줄이며 본다 | |
| ⑩ | 가로 스크롤바가 생기지 않는다. (R4) | 창 아래에 가로 막대가 보이는지 본다 | |
| ⑪ | 글과 취미 목록이 세로로 쌓여 보인다. (R4) | 좁힌 창에서 목록이 한 줄씩 아래로 내려가는지 본다 | |
| ⑫ | `index.html` 과 `style.css` 에 한국어 주석이 있다. | VS Code 에서 열어 `<!--` 나 `/*` 로 시작하는 한국어 설명을 찾는다 | |
| ⑬ | 자바스크립트(`<script>`)가 없다. | VS Code 에서 `<script` 를 검색한다. 0건이어야 한다 | |
| ⑭ | 외부 파일을 가져오는 줄(`http`, `https`)이 없다. | VS Code 에서 `http` 를 검색한다. 0건이어야 한다 | |

**확인 방법 주의:** 창을 줄였는데 글이 잘리면 ⑨ 는 `[ ]` 로 두고 6단계로 갑니다. 보이지 않는 것을 `[x]` 하면 안 됩니다.

## 6단계. 실패한 항목 고치게 하기 (15분)

**무엇을:** `[ ]` 로 남은 항목이 있으면, 그 **번호**를 AI 에게 알려 줍니다.

**[AI]**

```text
확인기록.md 의 [번호]번 항목이 안 돼. 지금 보이는 모습은 [무엇이 보이는지 한 문장]이야. 원인을 먼저 설명하고, 내가 "진행"이라고 하면 index.html 과 style.css 만 고쳐 줘. CHECKLIST.md 는 고치지 마.
```

예: `확인기록.md 의 ⑨번 항목이 안 돼. 지금 보이는 모습은 창을 줄이면 이메일 링크가 오른쪽으로 밀려 나가는 것이야.` (번호는 `①`처럼 쓰지 말고 `9번`처럼 씁니다.)

AI 가 원인을 설명하면 `진행` 을 입력합니다. 고친 뒤에는 **3단계부터 5단계까지 다시** 확인하고 기록을 갱신합니다.

## 7단계. 마지막 두 항목 확인하고 저장하기 (15분)

**무엇을:** `확인기록.md` 의 마지막 두 항목을 확인합니다.

| 번호 | 확인기록.md 의 문장 (그대로) | 맞으면 `[x]` |
|---|---|---|
| ⑮ | 위의 모든 항목을 확인했다. | 1~14번이 모두 `[x]` 일 때만 |
| ⑯ | 바꾼 파일과 확인 방법을 내가 말로 설명할 수 있다. | 파일 이름과 확인 방법을 소리 내어 한 번 말해 본 뒤에만 |

**[컨테이너]**

```bash
cd /workspace/card4
grep -c "\[ \]" 확인기록.md
```

`0` 이 나와야 저장합니다. `0` 이 아니면 6단계로 돌아갑니다.

`0` 이면 저장합니다. 저장은 사람이 합니다.

**[컨테이너]**

```bash
git add -A
git status
git commit -m "5장: 명함 페이지 완성 (확인기록 16개 항목 확인)"
git log --oneline
```

`git status` 에 `확인기록.md` 가 보여도 괜찮습니다. 함께 저장합니다.

---

## 확인 체크리스트
- [ ] `확인기록.md` 에 `[ ]` 가 0건이다.
- [ ] `CHECKLIST.md` 원본에는 `[x]` 가 한 개도 없다. (`grep -c "\[x\]" CHECKLIST.md` 가 0)
- [ ] 실패 항목이 있었다면, AI 에게 번호로 알리고 고치게 했다.
- [ ] `git log --oneline` 에 커밋이 한 줄 생겼다.

## 자주 만나는 오류

| 증상 | 해결 |
|---|---|
| `CHECKLIST.md` 원본에 `[x]` 가 생겼다 | 원본을 실수로 고친 것이다. `cp /tutorial/templates/stage0/CHECKLIST.md .` 를 쳐서 원본을 다시 복사한다. |
| `git commit` 이 `Please tell me who you are` | `.env` 의 `GIT_NAME`, `GIT_EMAIL` 을 채우고 컨테이너를 다시 들어간다. |
| 브라우저에서 index.html 이 안 열린다 | 파일 이름이 `index.html` 인지 확인한다. 탐색기에서 확장자가 보이도록 설정돼 있는지 본다. |
