# 0단계 3장. 작업 지시서 쓰기

> **실행 환경: 도커.** 명령 블록은 컨테이너 안(bash)에서 칩니다. `[Windows]` 로 표시된 블록만 Windows PowerShell 에서 칩니다. 파일 편집은 Windows 의 VS Code 에서 합니다. 자세한 설명은 [도커로 실행하기](../docker/00_도커로_실행하기.md)를 봅니다.

| | |
|---|---|
| 시간 | 1시간 30분 |
| 준비물 | 2장의 `내명함.md` |
| 결과 | 지시서 `지시서.md` 를 여섯 칸 워크시트로 완성하고, AI 가 낸 계획을 검토해 승인한다 |

## 이 장에서 할 일 한눈에 보기

1. 지시서 파일을 만든다. (5분)
2. 여섯 칸을 워크시트대로 채운다. (30분)
3. AI 에게 지시서를 건네고, 계획을 받는다. (15분)
4. 계획을 체크리스트로 검토하고, 고치게 하거나 승인한다. (20분)
5. 한 줄 지시와 지시서 지시의 차이를 표로 적는다. (20분)

---

## 1단계. 지시서 파일 만들기 (5분)

**[컨테이너]**

```bash
mkdir -p /workspace/card-task
cd /workspace/card-task
touch 지시서.md
ls -la
```

**[Windows]** VS Code 에서 `C:\harness-lab\card-task\지시서.md` 를 엽니다.

## 2단계. 여섯 칸 워크시트 채우기 (30분)

**무엇을:** `지시서.md` 에 아래 틀을 **그대로** 붙여 넣고, `[ ]` 칸을 채웁니다. 칸마다 "무엇을 쓰는지"와 "예"가 있으니 그대로 따릅니다.

```markdown
# 작업 지시서: 내 명함 페이지

## 1. 목표
[끝나면 무엇이 되어 있어야 하는지 한 문장]

## 2. 요구사항
[2장에서 쓴 내명함.md 의 요구사항 번호]

## 3. 범위
- 새로 만드는 파일: [파일 이름 두 개]
- 고치면 안 되는 파일: [파일 이름 두 개]

## 4. 하지 말 것
- [하지 말아야 할 것 한 가지]
- [하지 말아야 할 것 한 가지]
- [하지 말아야 할 것 한 가지]

## 5. 완료 조건
- [ ] [확인할 수 있는 조건 한 가지]
- [ ] [확인할 수 있는 조건 한 가지]

## 6. 진행 방법
먼저 계획만 말한다. 내가 "진행"이라고 하기 전에는 파일을 만들지 않는다.
끝나면 만든 파일 이름과, 완료 조건 중 어느 것을 확인했는지 보고한다.
```

칸별 워크시트:

| 칸 | 무엇을 쓰나 | 예 (그대로 쓰지 말고 내 내용으로 바꾼다) |
|---|---|---|
| 1. 목표 | 파일 두 개로 된 명함 페이지 한 개 | 내명함.md 의 R1~R5 를 만족하는 명함 페이지를 index.html 과 style.css 로 만든다 |
| 2. 요구사항 | 2장 파일의 번호를 그대로 | R1, R2, R3, R4, R5 |
| 3. 범위 (새로 만드는 파일) | 이름 두 개 | index.html, style.css |
| 3. 범위 (고치면 안 되는 파일) | 이름 두 개 | CHECKLIST.md, AGENTS.md |
| 4. 하지 말 것 | 2장 "만들지 않는 것"에서 세 개를 골라 쓴다 | 자바스크립트, 그림 파일, 외부 글꼴 |
| 5. 완료 조건 | 눈으로 볼 수 있는 조건 두 개 | 파일이 두 개뿐이다 / 브라우저에서 이름이 가장 크게 보인다 |
| 6. 진행 방법 | 이미 적혀 있다. 고치지 않는다 | (그대로) |

**확인 기준:** 아래 세 가지를 보고 아니오가 있으면 고칩니다.
- [ ] `[` 가 남아 있지 않다.
- [ ] 5번 완료 조건이 "잘 보인다"처럼 흐리지 않다. 눈으로 보고 맞다/아니다를 말할 수 있다.
- [ ] 4번 하지 말 것에 적은 것이 2장 "만들지 않는 것"에 있다.

## 3단계. AI 에게 지시서 건네기 (15분)

**[컨테이너]**

```bash
cd /workspace/card-task
opencode
```

OpenCode 입력 칸에 아래 문장을 **그대로** 붙여 넣습니다.

**[AI]**

```text
지시서.md 를 읽고 그 지시대로 작업해 줘. 먼저 계획만 말하고, 내가 "진행"이라고 할 때까지 파일을 만들지 마.
```

AI 가 계획을 말하면 4단계로 갑니다. (아직 "진행"이라고 하지 않습니다.)

## 4단계. 계획 검토하기 (20분)

**무엇을:** AI 의 계획을 아래 표로 한 줄씩 검토합니다.

| 확인 질문 | 답 (예/아니오) | 아니오면 할 일 |
|---|---|---|
| 1. 계획이 만드는 파일이 index.html 과 style.css 두 개뿐인가? | | |
| 2. 계획에 자바스크립트, 그림, 외부 글꼴이 들어 있지 않은가? | | |
| 3. 계획이 CHECKLIST.md 나 AGENTS.md 를 고치겠다고 하지 않는가? | | |
| 4. 계획에 2장 요구사항 R1~R5 가 모두 들어 있는가? | | |

**아니오가 있으면,** 아래 문장을 그대로 붙여 넣고, 아니오 항목 번호만 바꿉니다.

**[AI]**

```text
계획 중 [번호]번이 지시서의 "하지 말 것" 또는 "범위"와 맞지 않아. 그 부분을 빼고 계획을 다시 말해 줘. 아직 파일은 만들지 마.
```

모든 답이 예이면 아래 문장을 입력합니다.

**[AI]**

```text
진행
```

끝나면 `/exit` 를 칩니다.

## 5단계. 결과와 지시서 대조하기 (20분)

**[컨테이너]**

```bash
cd /workspace/card-task
ls -la
```

**무엇을:** 만들어진 파일을 지시서의 3번 칸과 대조합니다.

| 지시서 항목 | 실제 결과 | 같은가? |
|---|---|---|
| 3번 새로 만드는 파일 두 개 | | |
| 3번 고치면 안 되는 파일 (CHECKLIST.md 등) | | |
| 4번 하지 말 것 (그림, 스크립트 등이 있는가) | | |

**Windows 에서 확인:** `C:\harness-lab\card-task\index.html` 을 더블클릭해 브라우저로 엽니다. 5번 완료 조건 첫 항목을 눈으로 확인합니다. 결과를 표에 적습니다.

## 6단계. 한 줄 지시와 지시서 지시 비교하기 (20분)

**무엇을:** 1장 실험 A 의 결과와 이번 결과를 같은 항목끼리 적습니다.

| 항목 | 1장 실험 A (한 줄 지시) | 3장 (지시서) |
|---|---|---|
| 계획을 먼저 말했는가? | | |
| 시키지 않은 것이 있었는가? | | |
| 완료를 확인할 방법이 있었는가? | | |

비교 기준: 같은 항목의 두 칸에 "있었다/없었다" 또는 "예/아니오" 로 적어야 합니다. 설명이 길면 한 단어로 줄입니다.

---

## 확인 체크리스트
- [ ] `지시서.md` 의 여섯 칸을 모두 채웠다. `[` 가 남지 않았다.
- [ ] 계획 검토 네 항목을 모두 답했고, 아니오는 고쳤다.
- [ ] 5단계의 세 항목을 대조했다.
- [ ] 6단계 비교표를 채웠다.

## 자주 만나는 오류

| 증상 | 해결 |
|---|---|
| AI 가 `지시서.md` 를 찾지 못한다 | 명령을 `cd /workspace/card-task` 한 뒤에 `opencode` 를 쳤는지 확인한다. |
| AI 가 "진행"을 기다리지 않고 만든다 | 입력한 문장에 "먼저 계획만 말하고"가 있었는지 확인한다. 이미 만들었다면 `/undo` 를 친다. |
| 파일이 다른 폴더에 생겼다 | `pwd` 로 현재 폴더를 확인하고, 파일을 같은 폴더로 옮긴다. |
