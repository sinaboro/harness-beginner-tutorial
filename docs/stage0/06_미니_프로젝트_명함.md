# 0단계 6장. 미니 프로젝트: 자기소개 명함 페이지

> **실행 환경: 도커.** 명령 블록은 컨테이너 안(bash)에서 칩니다. `[Windows]` 로 표시된 블록만 Windows PowerShell 에서 칩니다. 파일 편집은 Windows 의 VS Code 에서 합니다. 자세한 설명은 [도커로 실행하기](../docker/00_도커로_실행하기.md)를 봅니다.

| | |
|---|---|
| 시간 | 2시간 |
| 준비물 | 1~5장 완료. 2장의 `내명함.md` 와 4장의 `AGENTS.md` 가 있다 |
| 결과 | 내 명함 페이지를 AI 에게 맡기고, 확인기록의 16개 항목을 모두 확인한 뒤 저장한다 |

## 이 장에서 할 일 한눈에 보기

1. 작업 폴더를 만들고, 앞 장의 파일을 옮겨 온다. (15분)
2. 요구사항 파일이 내 정보로 채워졌는지 대조한다. (15분)
3. AI 에게 맡기고 계획을 검토한다. (25분)
4. 확인기록의 16개 항목을 확인한다. (30분)
5. 과정 기록 `기록.md` 를 채우고 저장한다. (25분)

> 이 장은 **정답 파일을 주지 않습니다.** 요구사항과 체크리스트를 기준으로 확인합니다.

## 1단계. 작업 폴더 만들고 앞 장의 파일 옮기기 (15분)

**[컨테이너]**

```bash
mkdir -p /workspace/my-card
cd /workspace/my-card
cp /workspace/card-req/내명함.md REQUIREMENTS.md
cp /workspace/card4/AGENTS.md .
cp /workspace/card4/opencode.jsonc .
cp /tutorial/templates/stage0/TASK_명함.md .
cp /tutorial/templates/stage0/CHECKLIST.md .
git init
ls -la
```

`ls -la` 결과에 아래 다섯 개가 모두 있어야 합니다.

| 파일 | 어디서 왔나 | 있는가? (예/아니오) |
|---|---|---|
| REQUIREMENTS.md | 2장의 내명함.md 를 옮긴 것 | |
| AGENTS.md | 4장의 AGENTS.md | |
| opencode.jsonc | 4장의 권한 설정 | |
| TASK_명함.md | 템플릿 (지시서) | |
| CHECKLIST.md | 템플릿 (확인 기준) | |

아니오가 있으면, 그 파일이 있는 폴더를 `ls -la` 로 확인하고 다시 `cp` 합니다.

## 2단계. 요구사항이 내 정보로 채워졌는지 대조하기 (15분)

**무엇을:** `REQUIREMENTS.md` 에 대괄호 `[ ]` 가 남아 있지 않은지, 그리고 내 정보가 들어 있는지 확인합니다.

**[컨테이너]**

```bash
cd /workspace/my-card
grep -c "\[" REQUIREMENTS.md
grep -n "이메일\|이름\|취미" REQUIREMENTS.md
```

확인 기준:
- 첫 명령의 결과가 `0` 이어야 합니다. `0` 이 아니면 2장 3단계의 칸을 다시 채웁니다.
- 둘째 명령의 결과에 내 이름, 내 취미 세 개, 내 이메일 주소가 보여야 합니다.

**대조 방법:** `REQUIREMENTS.md` 를 VS Code 로 열고 아래 표를 채웁니다.

| 항목 | 파일에 적힌 내용 (그대로 옮겨 적는다) | 내 정보와 같은가? |
|---|---|---|
| R1 이름 | | |
| R1 한 줄 소개 | | |
| R2 취미 세 개 | | |
| R3 이메일 주소 | | |

`같은가?` 칸이 "아니오"이면 `REQUIREMENTS.md` 의 그 줄을 VS Code 에서 고칩니다. 바꾼 뒤 `grep -c "\[" REQUIREMENTS.md` 를 다시 쳐서 `0` 을 확인합니다.

## 3단계. AI 에게 맡기고 계획 검토하기 (25분)

**[컨테이너]**

```bash
cd /workspace/my-card
opencode
```

OpenCode 입력 칸에 아래 문장을 **그대로** 입력합니다.

**[AI]**

```text
TASK_명함.md 를 읽고 그 지시대로 작업해 줘. REQUIREMENTS.md 의 내용을 기준으로 삼는다. AGENTS.md 의 작업 순서를 지켜서, 먼저 계획만 말하고 내 승인을 기다려.
```

AI 의 계획을 아래 네 질문으로 검토합니다.

| 질문 | 답 (예/아니오) | 아니오면 할 일 |
|---|---|---|
| 1. 만드는 파일이 index.html 과 style.css 두 개뿐인가? | | |
| 2. 계획에 자바스크립트, 그림, 외부 글꼴이 없는가? | | |
| 3. 계획이 CHECKLIST.md, AGENTS.md, REQUIREMENTS.md 를 고친다고 하지 않는가? | | |
| 4. 계획이 R1~R5 를 모두 다루는가? | | |

**아니오가 있으면** 아래 문장을 입력하고 번호만 바꿉니다.

**[AI]**

```text
계획 [번호]번이 지시서의 "하지 말 것" 또는 "범위"와 맞지 않아. 그 부분을 빼고 계획을 다시 말해 줘. 아직 파일은 만들지 마.
```

모두 예이면 입력합니다.

**[AI]**

```text
진행
```

끝나면 `/exit` 를 칩니다.

## 4단계. 확인기록의 16개 항목 확인하기 (30분)

**무엇을:** 5장과 **같은 방법**으로 확인합니다. 원본 `CHECKLIST.md` 는 고치지 않고, 복사본 `확인기록.md` 에 체크합니다.

**[컨테이너]**

```bash
cd /workspace/my-card
cp CHECKLIST.md 확인기록.md
ls -la
```

**[Windows]** VS Code 에서 `C:\harness-lab\my-card\확인기록.md` 를 엽니다. 항목은 위에서부터 셉니다. 첫 번째 `- [ ]` 줄이 ①, 열여섯 번째가 ⑯ 입니다.

확인 순서:
1. ①~④: 파일 두 개, 메모장 글자, 더블클릭 열림, 이름이 가장 큼. → 5장 3단계의 방법대로 확인합니다.
2. ⑤~⑦: 한 줄 소개, 취미 세 줄, 이메일 링크. → 취미 줄 수는 브라우저에서 센다. 링크는 한 번 누른다.
3. ⑧~⑭: 색, 창 좁히기, 스크롤바, 세로 쌓임, 한국어 주석, `<script` 없음, `http` 없음. → 5장 5단계의 방법대로 확인합니다.
4. 실패한 번호가 있으면 AI 에게 번호로 알리고 고치게 합니다. 고친 뒤에는 1~3번 순서를 다시 확인합니다.

AI 에게 알리는 문장:

**[AI]**

```text
확인기록.md 의 [번호]번 항목이 안 돼. 지금 보이는 모습은 [무엇이 보이는지 한 문장]이야. 원인을 먼저 설명하고, 내가 "진행"이라고 하면 index.html 과 style.css 만 고쳐 줘. CHECKLIST.md 와 REQUIREMENTS.md 는 고치지 마.
```

⑮와 ⑯은 ⑭까지 모두 `[x]` 인 뒤에만 체크합니다.

**[컨테이너]**

```bash
cd /workspace/my-card
grep -c "\[ \]" 확인기록.md
diff CHECKLIST.md /tutorial/templates/stage0/CHECKLIST.md && echo "원본 체크리스트는 그대로입니다"
```

확인 기준: 첫 명령은 `0`, 둘째 명령은 "원본 체크리스트는 그대로입니다"가 나와야 합니다.

## 5단계. 과정 기록 쓰고 저장하기 (25분)

**무엇을:** `기록.md` 를 만들고 아래 틀의 빈칸을 채웁니다. 빈칸마다 질문이 있으니, 그 질문에 한 문장으로 답합니다.

**[컨테이너]**

```bash
cd /workspace/my-card
touch 기록.md
```

**[Windows]** VS Code 에서 `C:\harness-lab\my-card\기록.md` 를 열고 아래 틀을 붙여 넣습니다.

```markdown
# 6장 기록

## 1. AI 에게 시킨 일
질문: TASK_명함.md 의 목표 칸을 한 문장으로 옮겨 쓰시오.
답:

## 2. AI 계획에서 고치게 한 것
질문: 계획 검토 네 질문 중 아니오였던 것이 있었나? 있었다면 번호와 무엇을 고치게 했는지 쓰시오. 없었다면 "없음"이라고 쓰시오.
답:

## 3. 실패한 확인 항목과 고친 방법
질문: 확인기록에서 처음에 체크하지 못한 번호는? 어떻게 고쳤는지 한 문장으로 쓰시오. 없었다면 "없음".
답:

## 4. 내가 이해한 것 세 문장
질문: index.html 과 style.css 가 각각 무엇을 맡는지, 그리고 확인기록이 저장 전에 왜 필요한지 쓰시오.
답:
1.
2.
3.

## 5. 1장 실험 A 와 이번 장의 차이 한 가지
질문: 조건 없이 시켰을 때와 지시서로 시켰을 때, 가장 크게 달라진 것은 무엇인가?
답:
```

확인 기준: 모든 `답:` 칸의 `답:` 뒤에 글자가 있어야 합니다. 질문을 다시 읽고, 빈칸은 한 문장으로 채웁니다.

**[컨테이너]**

```bash
cd /workspace/my-card
grep -c "^답:\s*$" 기록.md
```

`grep` 결과가 `0` 이면 모든 답을 채운 것입니다. 결과가 0이 아니면 `답:` 줄 뒤에 아무 글자도 없는 곳이 있습니다. 그 칸을 찾아 채웁니다.

저장합니다. 저장은 사람이 합니다.

**[컨테이너]**

```bash
cd /workspace/my-card
git add -A
git status
git commit -m "6장: 나의 자기소개 명함 완성 (확인기록 16개 항목 확인, 기록 작성)"
git log --oneline
```

`git status` 에 `books.json` 같은 실습 파일 말고 `index.html`, `style.css`, `확인기록.md`, `기록.md` 가 보이면 정상입니다.

## 확인 체크리스트
- [ ] 1단계 파일 다섯 개가 모두 있다.
- [ ] `REQUIREMENTS.md` 에 `[` 가 0건이고, 내 정보가 들어 있다.
- [ ] 계획 검토 네 질문에 모두 답했다.
- [ ] 확인기록의 ①~⑯을 모두 `[x]` 했다. (`grep -c "\[ \]"` 가 0)
- [ ] `CHECKLIST.md` 원본이 바뀌지 않았다. (`diff` 결과가 없다)
- [ ] `기록.md` 의 다섯 답을 모두 썼다.
- [ ] `git log --oneline` 에 커밋이 한 줄 생겼다.

## 막혔을 때

| 증상 | 해결 |
|---|---|
| 1단계에서 `cp` 가 "No such file" 이라고 한다 | 앞 장의 폴더 이름을 확인한다. 2장은 `/workspace/card-req`, 4장은 `/workspace/card4` 이다. |
| AI 가 `REQUIREMENTS.md` 를 고치려 한다 | 기준은 사람이 고친다. AI 에게 "REQUIREMENTS.md 는 고치지 마"라고 말하고, 그래도 바뀌었다면 `diff` 로 확인해 원래대로 되돌린다. |
| 확인기록의 번호를 헷갈린다 | 5장의 "번호 세는 법"을 다시 읽는다. 제목 줄은 세지 않는다. |
| `git commit` 이 `Please tell me who you are` | `.env` 의 `GIT_NAME`, `GIT_EMAIL` 을 채우고 컨테이너를 다시 들어간다. |
