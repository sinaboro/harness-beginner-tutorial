# 0단계 6장. 미니 프로젝트: 자기소개 명함 페이지

> **실행 환경: 도커.** 명령 블록은 컨테이너 안(bash)에서 칩니다. `[Windows]` 로 표시된 블록만 Windows PowerShell 에서 칩니다. 파일 편집은 Windows 의 VS Code 에서 합니다. 자세한 설명은 [도커로 실행하기](../docker/00_도커로_실행하기.md)를 봅니다.

| | |
|---|---|
| 시간 | 2시간 |
| 준비물 | 1~5장 완료 |
| 결과 | 명함 페이지를 AI 에게 맡기고, 체크리스트로 확인해 저장한다. 과정 기록을 쓴다. |

## 학습 목표
1. 1~5장의 요소(요구사항, 지시서, 규칙, 권한, 체크리스트, 저장)를 한 프로젝트에 모두 쓴다.
2. 내 이름과 취미로 명함을 채운다.
3. 체크리스트가 통과한 것만 저장한다.

---

## 1. 개념 — 지금까지의 고리

```text
 ① 요구사항  (REQUIREMENTS.md)           무엇을 만들지 약속한다        ← 2장
 ② 작업 지시서 (TASK_명함.md)              어디까지 맡길지 정한다        ← 3장
 ③ 규칙과 권한 (AGENTS.md, opencode.jsonc) AI 의 행동 범위를 정한다     ← 4장
 ④ 확인 (CHECKLIST.md)                   사람이 직접 본다              ← 5장
 ⑤ 저장 (git commit)                     확인이 끝난 것만 저장한다      ← 5장
```

사람이 하는 일은 요구사항의 내용(내 정보)을 채우고, 계획을 승인하고, 체크리스트를 직접 보고, 저장하는 것입니다. 파일은 AI 가 만듭니다.

---

## 2. 따라 하기

### 1단계. 작업 폴더 만들기 (10분)

**[컨테이너]**

```bash
mkdir -p /workspace/my-card
cd /workspace/my-card
T="/tutorial/templates/stage0"
cp "$T/opencode.jsonc" .
cp "$T/CHECKLIST.md" .
cp "$T/AGENTS_빈칸.md" AGENTS.md
cp "$T/REQ_명함.md" REQUIREMENTS.md
cp "$T/TASK_명함.md" TASK.md
git init
echo ".env" > .gitignore
ls -la
```

### 2단계. 내 정보 채우기 (15분)

`REQUIREMENTS.md` 의 **R1 과 R2** 에 내 정보를 적습니다. 요구사항의 틀은 그대로 두고, 내용만 바꿉니다.

**[Windows]**

```bash
# (Windows) REQUIREMENTS.md 을(를) VS Code 로 열어 고칩니다
```

R1 에는 이름과 한 줄 소개, R2 에는 취미 세 개를 적습니다. 그 밖의 요구사항은 그대로 둡니다.

### 3단계. AGENTS.md 채우기 (20분)

**[Windows]**

```bash
# (Windows) AGENTS.md 을(를) VS Code 로 열어 고칩니다
```

4장에서 쓴 것을 옮깁니다. 꼭 들어갈 다섯 문장이 있는지 확인합니다.

- [ ] 계획을 먼저 말하고 "진행"을 기다린다.
- [ ] CHECKLIST.md 를 고치지 않는다.
- [ ] 저장은 하지 않는다.
- [ ] 완료라고 말하기 전 체크리스트를 확인한다.
- [ ] 바뀐 파일과 확인한 항목을 보고한다.

### 4단계. AI 에게 맡기기 (30분)

**[컨테이너]**

```bash
opencode
```

**[AI]**

```text
TASK.md 를 읽고 그 지시대로 작업해 줘. REQUIREMENTS.md 의 내용을 따른다. AGENTS.md 의 작업 순서를 지켜서, 먼저 계획만 말하고 내 승인을 기다려.
```

계획을 검토합니다.

- [ ] 고칠 파일이 index.html, style.css 뿐인가?
- [ ] 자바스크립트, 그림, 외부 파일을 쓰겠다는 말이 없는가?
- [ ] CHECKLIST.md 를 고치겠다는 말이 없는가?

맞으면 `진행` 이라고 답합니다.

### 5단계. 체크리스트로 확인하기 (30분)

AI 가 끝나면 `/exit` 로 나옵니다. `CHECKLIST.md` 를 열고 1단계부터 확인합니다.

**[컨테이너]**

```bash
ls -la
# (Windows) CHECKLIST.md 을(를) VS Code 로 열어 고칩니다
# (Windows) index.html 을(를) 탐색기에서 더블클릭합니다
```

- 내 이름이 가장 크게 보이는가? 소개와 취미가 맞는가?
- 이메일 링크를 누르면 작성 창이 열리는가?
- 창을 좁혀도 글이 잘리지 않는가?

**내가 확인하지 않은 항목은 체크하지 않습니다.**

실패한 항목이 있다면 AI 에게 말합니다.

**[AI]**

```text
CHECKLIST.md 의 항목 중 실패한 것이 있어. 어떤 항목인지 내가 말할게. 원인을 먼저 설명하고, 내가 "진행"이라고 하면 index.html 과 style.css 만 고쳐 줘. CHECKLIST.md 는 고치지 마.
```

### 6단계. 저장하기 (10분)

모든 항목을 확인했다면 저장합니다.

**[컨테이너]**

```bash
git add -A
git status
git commit -m "6장: 나의 자기소개 명함 완성 (체크리스트 확인 완료)"
git log --oneline
```

### 7단계. 과정 기록 쓰기 (10분)

`기록.md` 를 만들고 아래를 채웁니다.

```markdown
# 6장 기록

## 1. AI 에게 시킨 일 (한 문장)

## 2. AI 의 계획 중 고치게 한 것 (없으면 "없음")

## 3. 실패한 체크 항목과 고친 방법

## 4. 내가 이해한 것 세 문장
1.
2.
3.

## 5. 새로 알게 된 것 한 가지
```

**[Windows]**

```bash
# (Windows) 기록.md 을(를) VS Code 로 열어 고칩니다
```

---

## 3. 확인하기
- [ ] 명함에 내 이름, 소개, 취미 세 개가 들어 있다.
- [ ] 체크리스트의 모든 항목을 내가 직접 확인했다.
- [ ] 저장 커밋이 한 줄 생겼다.
- [ ] 기록에 설명 세 문장을 썼다.

## 4. 막혔을 때
- 페이지가 깨졌다면 CHECKLIST.md 의 해당 항목을 AI 에게 가리키며 원인부터 설명하게 합니다.
- AI 가 체크리스트를 고치려 하면 권한 설정(opencode.jsonc)이 막습니다. 막히지 않았다면 `git status` 로 확인해 되돌립니다.
- 정답 파일은 제공하지 않습니다. 요구사항과 체크리스트를 기준으로 AI 와 대화하며 맞춰 갑니다.

## 5. 확인 문제
1. 이번 장에서 사람이 한 판단을 세 가지 쓰시오.
2. 체크하지 않은 항목이 있는데 저장하면 어떤 일이 생기는가?
3. 1장 실험 A 와 이번 장을 비교했을 때 달라진 점을 두 가지 쓰시오.
