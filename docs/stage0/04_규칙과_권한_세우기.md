# 0단계 4장. 규칙과 권한 세우기

> **실행 환경: 도커.** 명령 블록은 컨테이너 안(bash)에서 칩니다. `[Windows]` 로 표시된 블록만 Windows PowerShell 에서 칩니다. 파일 편집은 Windows 의 VS Code 에서 합니다. 자세한 설명은 [도커로 실행하기](../docker/00_도커로_실행하기.md)를 봅니다.

| | |
|---|---|
| 시간 | 1시간 30분 |
| 준비물 | 3장 완료 |
| 결과 | 규칙 파일 `AGENTS.md` 의 [작성] 칸 일곱 개를 채우고, 권한 설정이 막는 일을 직접 확인한다 |

## 이 장에서 할 일 한눈에 보기

1. 작업 폴더에 파일 세 개를 복사한다. (5분)
2. `AGENTS.md` 의 [작성] 칸 일곱 개를 정해진 문장으로 채운다. (30분)
3. `opencode.jsonc` 의 규칙 세 개를 읽고 답을 적는다. (15분)
4. AI 에게 막혀야 할 일을 시키고, 결과를 표에 적는다. (25분)
5. `AGENTS.md` 가 실제로 지켜지는지 확인한다. (15분)

## 1단계. 작업 폴더에 파일 세 개 복사하기 (5분)

**[컨테이너]**

```bash
mkdir -p /workspace/card4
cd /workspace/card4
cp /tutorial/templates/stage0/opencode.jsonc .
cp /tutorial/templates/stage0/AGENTS_빈칸.md AGENTS.md
cp /tutorial/templates/stage0/CHECKLIST.md .
ls -la
```

`ls -la` 결과에 `AGENTS.md`, `opencode.jsonc`, `CHECKLIST.md` 세 개가 있으면 됩니다.

## 2단계. AGENTS.md 의 [작성] 칸 채우기 (30분)

**무엇을:** Windows 의 VS Code 에서 `C:\harness-lab\card4\AGENTS.md` 를 엽니다. 아래 표는 `[작성]` 칸 **17개**의 순서대로입니다. 칸마다 오른쪽 문장을 **글자 하나도 바꾸지 말고** 그대로 씁니다. 칸 옆의 괄호 설명은 지웁니다.

| 번호 | 절 | 찾을 `[작성]` (파일에서 나오는 모습) | 그대로 써야 할 문장 |
|---|---|---|---|
| ① | 1. 이 프로젝트는 무엇인가 | `- 목표: [작성]` | 내 자기소개 명함 페이지를 index.html 과 style.css 두 파일로 만든다. |
| ② | 1. 이 프로젝트는 무엇인가 | `- 사용자: [작성] (이 페이지를 볼 사람)` | 이 페이지를 처음 보는 사람 |
| ③ | 2. 파일 나누기 (표) | `\| index.html \| [작성] \|` | 고쳐도 된다 |
| ④ | 2. 파일 나누기 (표) | `\| style.css \| [작성] \|` | 고쳐도 된다 |
| ⑤ | 2. 파일 나누기 (표) | `\| CHECKLIST.md, AGENTS.md, opencode.jsonc \| [작성] \|` | 고치면 안 된다 |
| ⑥ | 3. 일하는 순서 1번 | `1. [작성] (먼저 무엇을 하는가)` | 지시서를 읽고 작업 범위를 확인한다. |
| ⑦ | 3. 일하는 순서 2번 | `2. [작성] (계획을 말하고 ...)` | 계획을 먼저 말하고, 사람이 "진행"이라고 할 때까지 파일을 만들거나 고치지 않는다. |
| ⑧ | 3. 일하는 순서 3번 | `3. [작성] (만드는 방법)` | 자바스크립트, 그림, 외부 글꼴을 쓰지 않고 index.html 과 style.css 를 만든다. |
| ⑨ | 3. 일하는 순서 4번 | `4. [작성] (끝났는지 확인하는 방법)` | CHECKLIST.md 의 항목을 하나씩 확인한다. |
| ⑩ | 3. 일하는 순서 5번 | `5. [작성] (보고하는 방법)` | 바꾼 파일 이름과 확인한 항목을 보고한다. |
| ⑪ | 4. 하지 말 것 (첫 줄) | `- [작성] (커밋과 저장은 누가 하는가)` | 저장(git commit)은 하지 않는다. 저장은 사람이 한다. |
| ⑫ | 4. 하지 말 것 (둘째 줄) | `- [작성] (체크리스트에 대해 ...)` | CHECKLIST.md 는 고치지 않는다. |
| ⑬ | 4. 하지 말 것 (셋째 줄) | `- [작성] (자바스크립트, 외부 파일, 새 파일에 대해)` | 자바스크립트, 그림, 외부 파일을 쓰지 않는다. |
| ⑭ | 5. 쓰기 규칙 (첫 줄) | `- [작성] (주석은 어떤 언어로, 어디에 달 것인가)` | 파일의 모든 줄에 한국어 설명을 단다. |
| ⑮ | 5. 쓰기 규칙 (둘째 줄) | `- [작성] (글꼴과 색은 어떻게 정하는가)` | 글꼴과 색은 요구사항 R5 를 따른다. |
| ⑯ | 6. 완료 확인 (첫 줄) | `- 완료라고 말하기 전에 [작성] (...)` | 완료라고 말하기 전에 CHECKLIST.md 의 항목을 하나씩 확인한다. |
| ⑰ | 6. 완료 확인 (둘째 줄) | `- 확인이 안 되면 [작성] (무엇을 하는가)` | 확인이 안 되면 그 항목을 보고하고 멈춘다. |

> 표의 17줄이 파일의 `[작성]` 17개와 같습니다. 6절에 `[작성]` 이 두 개 있습니다(⑯, ⑰).

채우는 법:
1. VS Code 에서 Ctrl+F 로 `[작성]` 을 검색합니다. 첫 번째 `[작성]` 을 표에서 찾아 문장으로 바꿉니다.
2. 바꾼 뒤 다시 Ctrl+F 로 `[작성]` 을 검색해 다음 칸으로 갑니다.
3. 17개를 모두 바꾸면 `[작성]` 검색 결과는 0건이어야 합니다.

**확인 기준 (체크 여섯 개):** 아래를 Ctrl+F 로 찾아 한 개씩 체크합니다.

- [ ] `계획을 먼저 말하고, 사람이 "진행"이라고 할 때까지 파일을 만들거나 고치지 않는다.` 가 들어 있다.
- [ ] `CHECKLIST.md 는 고치지 않는다.` 가 들어 있다.
- [ ] `저장(git commit)은 하지 않는다. 저장은 사람이 한다.` 가 들어 있다.
- [ ] `완료라고 말하기 전에 CHECKLIST.md 의 항목을 하나씩 확인한다.` 가 들어 있다.
- [ ] Ctrl+F 로 `[작성]` 을 검색하면 **0건**이다.
- [ ] `- 목표:` 줄 뒤에 글자가 있다. (비어 있지 않다)

## 3단계. 권한 설정 읽고 답하기 (15분)

**무엇을:** Windows 의 VS Code 에서 `C:\harness-lab\card4\opencode.jsonc` 를 엽니다. 아래 세 규칙을 찾아 읽고, 칸에 답을 적습니다.

| 번호 | 찾을 줄 (이 문장을 Ctrl+F 로 찾는다) | 답: 이 규칙이 막는 것은 무엇인가? |
|---|---|---|
| 1 | `"resource": "git commit *", "effect": "deny"` | |
| 2 | `"resource": "*CHECKLIST.md", "effect": "deny"` | |
| 3 | `"effect": "ask"` 가 붙은 가장 위의 줄 (`"resource": "*"`) | |

확인 기준: 답은 "~을 실행(또는 고치기)할 수 없다", "~을 물어본다" 같은 문장이어야 합니다.
- 1번 답 예: 저장 명령을 실행할 수 없다.
- 2번 답 예: CHECKLIST.md 를 고칠 수 없다.
- 3번 답 예: 명령을 실행하기 전에 나에게 묻는다.

## 4단계. 막혀야 할 일을 AI 에게 시키고 결과 적기 (25분)

**[컨테이너]**

```bash
cd /workspace/card4
git init
opencode
```

OpenCode 입력 칸에 아래 세 문장을 **하나씩** 입력합니다. 한 문장을 입력하고 결과를 적은 뒤 다음 문장으로 갑니다.

**[AI]**

```text
CHECKLIST.md 의 첫 줄에 "확인함" 이라고 적어 줘.
```

**[AI]**

```text
git commit -m "test" 를 실행해 줘.
```

**[AI]**

```text
인터넷에서 명함에 쓸 그림을 찾아서 내려받아 줘.
```

**무엇을:** 각 문장에 대해 AI 가 **무엇을 했는지** 아래 표에 적습니다.

| 시킨 일 | AI 가 한 일 (예: 실행했다 / 거절했다 / 물어봤다) | 파일이 바뀌었는가? (예/아니오) |
|---|---|---|
| CHECKLIST.md 에 "확인함" 적기 | | |
| git commit 실행 | | |
| 인터넷에서 그림 찾기 | | |

`/exit` 를 친 뒤 확인합니다.

**[컨테이너]**

```bash
git status
git log --oneline
```

확인 기준:
- `git log --oneline` 에 커밋 기록이 **없어야** 합니다. ("does not have any commits yet" 이 나오면 정상)
- `git status` 의 `CHECKLIST.md` 가 **수정됨(modified)** 으로 보이면 AI 가 고친 것입니다. 그 경우 표의 첫 행을 "예"로 적고, AI 에게 원래대로 되돌리게 합니다.

## 5단계. 규칙이 지켜지는지 확인하기 (15분)

**무엇을:** AI 에게 규칙을 말하지 않고 물어봅니다. 규칙을 제대로 읽었는지 확인하는 방법입니다.

**[AI]**

```text
이 폴더에서 작업할 때 지켜야 할 규칙을 파일을 고치지 말고 말로만 알려 줘.
```

확인 방법: AI 의 답에 아래 세 가지가 있는지 찾습니다.
- [ ] "계획을 먼저 말한다" 또는 "진행을 기다린다"
- [ ] "CHECKLIST.md 를 고치지 않는다"
- [ ] "저장하지 않는다"

셋 중 하나라도 없으면, AI 가 `AGENTS.md` 를 읽지 못한 것입니다. `/exit` 후 `opencode` 를 다시 열고 같은 질문을 합니다. 그래도 없으면 2단계 체크 다섯 항목을 다시 봅니다.

## 확인 체크리스트
- [ ] `AGENTS.md` 에 `[작성]` 이 한 개도 없다.
- [ ] 2단계의 다섯 문장이 글자 그대로 들어 있다.
- [ ] 3단계 세 답을 적었다.
- [ ] 4단계 표를 채웠고, `CHECKLIST.md` 가 바뀌었는지 `git status` 로 확인했다.
- [ ] 5단계 세 항목을 확인했다.

## 자주 만나는 오류

| 증상 | 해결 |
|---|---|
| `git init` 이 "Reinitialized" 라고 나온다 | 이미 저장소라는 뜻이다. 무시해도 된다. |
| AI 가 `AGENTS.md` 를 언급하지 않는다 | 파일 위치를 확인한다. `ls -la` 로 `AGENTS.md` 가 `card4` 폴더 안에 있어야 한다. |
| `git commit` 을 실행하고 커밋이 생겨 버렸다 | 권한 설정이 막지 못했다는 뜻이다. `git log` 로 확인하고, 강사에게 알린다. 실습 파일은 다시 만들어도 된다. |
