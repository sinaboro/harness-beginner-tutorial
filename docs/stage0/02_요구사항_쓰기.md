# 0단계 2장. 말로 된 요구사항 쓰기

> **실행 환경: 도커.** 명령 블록은 컨테이너 안(bash)에서 칩니다. `[Windows]` 로 표시된 블록만 Windows PowerShell 에서 칩니다. 파일 편집은 Windows 의 VS Code 에서 합니다. 자세한 설명은 [도커로 실행하기](../docker/00_도커로_실행하기.md)를 봅니다.

| | |
|---|---|
| 시간 | 1시간 30분 |
| 준비물 | 1장 완료 |
| 결과 | 내 명함 페이지의 요구사항 파일 `내명함.md` 를 칸 채우기 방식으로 완성한다 |

## 이 장에서 할 일 한눈에 보기

1. 흐린 말을 확인할 수 있는 말로 바꾼다. (15분)
2. 요구사항 파일 `내명함.md` 를 만든다. (20분)
3. 칸을 하나씩 채운다. 워크시트를 따른다. (35분)
4. 체크리스트로 점검하고 고친다. (15분)
5. 옆 사람과 바꿔 읽고 질문을 적는다. (15분)

---

## 1단계. 흐린 말 고치기 (15분)

**무엇을:** 아래 문장에서 흐린 낱말을 찾아 표에 옮기고, 각각을 **숫자나 눈으로 볼 수 있는 말**로 바꿔 씁니다.

> 명함은 예쁘고, 보기 좋고, 누구나 쉽게 읽을 수 있어야 한다.

| 흐린 말 | 눈으로 확인할 수 있는 말로 바꾼 것 (예: "바탕은 연한 회색이다") |
|---|---|
| 예쁘고 | |
| 보기 좋고 | |
| 쉽게 읽을 수 있어야 | |

**확인 기준:** 바꾼 말을 읽고 "눈으로 보면 '맞다/아니다'를 말할 수 있는가?"에 답합니다. 답할 수 없으면 다시 바꿉니다.

## 2단계. 요구사항 파일 만들기 (20분)

**무엇을:** 컨테이너 안에 작업 폴더를 만들고, 빈 파일 `내명함.md` 를 만듭니다. (파일 내용은 3단계에서 씁니다.)

**[컨테이너]**

```bash
mkdir -p /workspace/card-req
cd /workspace/card-req
touch 내명함.md
ls -la
```

**[Windows]** VS Code 에서 `C:\harness-lab\card-req\내명함.md` 를 엽니다.

> 예시 파일은 `/tutorial/templates/stage0/REQ_명함.md` 입니다(Windows 에서는 `C:\harness-beginner-tutorial\templates\stage0\REQ_명함.md`). **보기만 하고 복사하지 않습니다.** 내 파일은 직접 씁니다.

## 3단계. 워크시트대로 칸 채우기 (35분)

**무엇을:** `내명함.md` 에 아래 틀을 **그대로** 붙여 넣고, `[ ]` 로 된 칸만 채웁니다. 다른 줄은 바꾸지 않습니다.

```markdown
# 요구사항: 내 명함 페이지

## 기능 요구사항

### R1. 이름과 한 줄 소개
- 이렇게 하면: 페이지를 브라우저로 연다.
- 이런 결과가 나온다: 맨 위에 [내 이름]이 가장 큰 글씨로 보이고, 그 아래 [한 줄 소개]가 보인다.
- 잘못 쓰면: 이름이나 소개가 비어 있으면, 그 줄은 보이지 않고 페이지는 깨지지 않는다.

### R2. 취미 목록
- 이렇게 하면: 페이지를 브라우저로 연다.
- 이런 결과가 나온다: "취미"라는 제목 아래에 취미가 [세 개] 세로로 보인다. 취미 이름은 [취미1], [취미2], [취미3] 이다.
- 잘못 쓰면: 취미가 세 개가 아니어도 목록이 깨지지 않는다.

### R3. 연락 링크
- 이렇게 하면: "이메일 보내기" 링크를 누른다.
- 이런 결과가 나온다: 이메일 작성 창이 열리고, 받는 사람은 [내 이메일 주소] 이다.
- 잘못 쓰면: 이메일 주소가 비어 있으면 링크를 보여 주지 않는다.

### R4. 좁은 화면에서도 보기 좋게
- 이렇게 하면: 브라우저 창의 오른쪽 끝을 잡고 왼쪽으로 줄인다.
- 이런 결과가 나온다: 글과 목록이 가로로 잘리지 않고 세로로 쌓인다.
- 잘못 쓰면: 가로 스크롤바가 생기면 실패다.

### R5. 색과 글꼴
- 이렇게 하면: 페이지를 연다.
- 이런 결과가 나온다: 바탕은 [연한 회색 계열], 이름은 [진한 남색 계열]이다. 이름이 가장 큰 글씨다.

## 만들지 않는 것
- 로그인, 방명록, 입력 폼
- 그림 파일과 외부 글꼴
- 자바스크립트
```

칸 채우기 규칙 (대괄호 `[ ]` 칸마다 하나씩):

| 칸 | 무엇을 쓰나 | 예 |
|---|---|---|
| `[내 이름]` (R1) | 내 이름 한 개 | 홍길동 |
| `[한 줄 소개]` (R1) | 짧은 문장 한 개 | 배우는 것을 좋아하는 사람 |
| `[세 개]` (R2) | 그대로 둔다 | 세 개 |
| `[취미1]`, `[취미2]`, `[취미3]` (R2) | 취미 한 개씩 | 독서, 산책, 요리 |
| `[내 이메일 주소]` (R3) | 내 이메일 주소 | you@example.com |
| `[연한 회색 계열]`, `[진한 남색 계열]` (R5) | 이 두 칸은 바꾸지 않는다 | (그대로) |

**하는 법:** VS Code 에서 `[내 이름]` 을 찾아(Ctrl+F) 내 이름으로 바꿉니다. 칸마다 같은 방법으로 바꾸고, 대괄호 `[ ]` 는 모두 지웁니다.

**확인 기준:** `[` 또는 `]` 가 남아 있으면 칸을 다 채우지 않은 것입니다. 저장하고 다음 단계로 갑니다.

## 4단계. 체크리스트로 점검하고 고치기 (15분)

**무엇을:** 아래 여섯 항목을 **한 줄씩** 확인하고, 아니오가 있으면 `내명함.md` 를 고칩니다.

| 확인할 항목 | 확인 방법 | 예 / 아니오 |
|---|---|---|
| 1. 대괄호 `[` `]` 가 한 개도 남아 있지 않은가? | Ctrl+F 로 `[` 를 검색해 0건인지 본다 | |
| 2. R1~R5 각각에 "이렇게 하면", "이런 결과가 나온다", "잘못 쓰면" 세 줄이 있는가? | 다섯 번 세어 본다 | |
| 3. "이런 결과가 나온다" 줄에 "예쁘다, 잘 보인다, 편하다" 같은 흐린 말이 없는가? | 세 낱말을 검색해 0건인지 본다 | |
| 4. "만들지 않는 것"이 적혀 있는가? | 4번째 줄 근처를 본다 | |
| 5. R3 의 이메일 주소에 `@` 가 들어 있는가? | 검색해서 있는지 본다 | |
| 6. R2 의 취미가 세 개인가? | `[취미` 를 검색해 세 번 나오는지 본다 | |

아니오가 있으면, 그 항목을 고치고 그 항목의 번호를 옆에 적습니다.

## 5단계. 옆 사람과 바꿔 읽고 질문 적기 (15분)

**무엇을:** 옆 사람의 `내명함.md` 를 읽고, 질문을 **두 개 이상** 적습니다.

질문은 아래 형식으로 씁니다.

```text
R[번호] 에서 [무엇]이 궁금합니다. 예: "R1 에서 소개가 두 줄이면 어떻게 되나요?"
```

질문에 답이 적혀 있지 않으면, 그 항목은 빈틈입니다. 빈틈이 생긴 줄을 찾아 **그 줄을 한 문장 더 구체적으로** 고칩니다.

---

## 확인 체크리스트
- [ ] 1단계 표 세 줄을 모두 채웠다.
- [ ] `내명함.md` 가 있고, 대괄호 `[` `]` 가 남아 있지 않다.
- [ ] 4단계 여섯 항목을 모두 확인하고, 아니오는 고쳤다.
- [ ] 옆 사람의 파일에서 질문을 두 개 이상 적었다.

## 자주 만나는 오류

| 증상 | 해결 |
|---|---|
| `touch` 명령이 없다고 나온다 | 명령을 컨테이너 안에서 쳤는지 확인한다. (Windows 에서 치면 안 된다) |
| `내명함.md` 가 안 보인다 | 컨테이너 안에서 `ls -la` 를 친다. 없다면 `cd /workspace/card-req` 를 한 뒤 다시 `touch 내명함.md` 를 친다. |
| 파일을 저장했는데 바뀌지 않은 것 같다 | VS Code 에서 Ctrl+S 를 눌렀는지 확인한다. 탭 제목 옆에 점이 있으면 저장되지 않은 것이다. |
