# 2장. 요구사항 쓰기

> **실행 환경: 도커.** 명령은 컨테이너 안(bash)에서 칩니다. 교안의 PowerShell 명령은 [도커로 실행하기](../docker/00_도커로_실행하기.md)의 명령 대응표(4절)를 보고 바꿔 씁니다. 편집은 Windows 의 VS Code 에서 합니다.

| | |
|---|---|
| 시간 | 2시간 |
| 준비물 | 1장 완료. 메모장 또는 VS Code |
| 결과 | "이렇게 부르면 → 이런 결과" 형식으로 요구사항 한 장을 쓴다 |

## 학습 목표

1. 좋은 요구사항과 나쁜 요구사항을 구분한다.
2. 요구사항의 세 부분(이렇게 하면, 이런 결과가 나온다, 잘못 쓰면)을 채운다.
3. 모호한 낱말을 찾아 눈으로 확인할 수 있는 말로 바꾼다.

---

## 1. 개념 — 요구사항은 "약속"이다

요구사항은 "무엇을 만들지"를 사람끼리, 그리고 AI 와 약속하는 글입니다. 약속이 흐리면 AI 는 빈 곳을 제멋대로 채웁니다. 1장의 실험 A 에서 AI 가 나눗셈을 추가한 것도 약속이 없었기 때문입니다.

### 좋은 요구사항과 나쁜 요구사항

| 나쁜 요구사항 | 왜 나쁜가 | 좋은 요구사항 |
|---|---|---|
| 계산기를 만든다 | 무슨 계산인지 모른다 | 두 수를 받아 더한 결과를 돌려준다 |
| 빠르게 계산한다 | "빠르게"를 잴 방법이 없다 | 계산 결과는 즉시 화면에 나온다 (확인 방법: 실행하면 바로 답이 나온다) |
| 0 나누기도 잘 처리한다 | "잘"이 무엇인지 모른다 | 0으로 나누면 "0으로 나눌 수 없습니다."라는 오류를 낸다 |
| 적당히 예쁘게 만든다 | "적당히", "예쁘게"는 사람마다 다르다 | (이번 교안에서는 화면을 만들지 않는다) |

### 요구사항의 세 칸

| 칸 | 질문 | 예 |
|---|---|---|
| 이렇게 하면 | 무엇을 어떻게 부르나? | `add(2, 3)` 을 부른다 |
| 이런 결과가 나온다 | 무엇이 돌아오나? | `5` 가 돌아온다 |
| 잘못 쓰면 | 잘못된 입력일 때는? | `divide(1, 0)` 이면 `ValueError` 오류가 난다 |

**"잘못 쓰면" 칸이 가장 자주 빠집니다.** 빠진 칸은 AI 가 마음대로 정합니다.

## 2. 따라 하기

### 1단계. 나쁜 요구사항 고치기 (20분)

아래 문장을 읽고, 흐린 낱말에 밑줄을 긋습니다.

> 계산기는 숫자를 잘 계산하고, 빠르고 정확하며, 사용하기 편해야 한다.

흐린 낱말은 "잘", "빠르고", "정확하며", "편해야"입니다. 각각을 확인할 수 있는 문장으로 바꿉니다.

| 흐린 낱말 | 확인할 수 있는 문장으로 바꾸면 |
|---|---|
| 잘 계산한다 | 두 수 2와 3을 더하면 5가 나온다 |
| 빠르게 | |
| 정확하게 | |
| 편하게 | |

> 힌트: "편하게"는 쉽지 않습니다. 이번 교안에서는 화면을 만들지 않으므로, "편하게"를 요구사항에서 빼는 것도 답입니다. 빼는 것이 맞는 경우도 있습니다.

### 2단계. 요구사항 틀 채우기 (40분)

저장소의 빈칸 틀을 작업 폴더에 복사합니다.

**[PS]**

```powershell
New-Item -ItemType Directory C:\harness-lab\요구사항연습
Copy-Item C:\harness-beginner-tutorial\templates\REQ_빈칸.md C:\harness-lab\요구사항연습\요구사항.md
notepad C:\harness-lab\요구사항연습\요구사항.md
```

메모장에서 계산기 요구사항을 채웁니다. 조건은 다음과 같습니다.

- 기능은 **세 가지**만 씁니다: 더하기, 빼기, 나누기
- 나누기에는 반드시 "잘못 쓰면" 칸을 채웁니다.
- "만들지 않는 것"에 두 가지 이상을 적습니다. (예: 곱하기, 화면, 파일 저장)

### 3단계. 점검하기 (20분)

다 쓴 요구사항을 아래 질문으로 점검합니다. 하나라도 "아니오"면 고칩니다.

- [ ] 옆 사람이 읽고 똑같은 계산기를 만들 수 있는가?
- [ ] 모든 기능에 "이렇게 하면 / 이런 결과 / 잘못 쓰면"이 있는가?
- [ ] 결과를 눈으로 확인할 수 있는가? ("잘"이나 "편하게"가 없는가?)
- [ ] "만들지 않는 것"이 적혀 있는가?

### 4단계. 다른 사람과 바꿔 읽기 (20분)

옆 사람의 요구사항을 읽고, **읽는 사람 입장에서** 질문을 한 개씩 적어 줍니다. 질문이 많이 나오면 요구사항이 약하다는 뜻입니다.

예: "0으로 나누면 오류 메시지를 정확히 어떤 글자로 내나요?" → 이 질문에 답이 적혀 있지 않다면 고칩니다.

### 5단계. 예제와 비교하기 (10분)

저장소의 예제 코드를 읽고, 요구사항의 한 줄이 코드의 어디에 있는지 찾습니다.

**[PS]**

```powershell
type C:\harness-beginner-tutorial\examples\calc\calc.py
```

- `add` 함수 위의 설명 `"""두 수를 더한다."""` 는 요구사항의 어느 줄에 해당하나?
- `divide` 의 `if b == 0:` 은 요구사항의 어느 줄에 해당하나?

요구사항이 코드가 되는 과정을 눈으로 본 것입니다. 이 연결이 **테스트**가 됩니다(5장).

## 3. 확인하기

- [ ] 계산기 요구사항을 세 기능과 "잘못 쓰면" 칸까지 채웠다.
- [ ] "만들지 않는 것"을 두 가지 이상 적었다.
- [ ] 옆 사람의 요구사항에서 질문을 하나 이상 찾았다.

## 4. 자주 만나는 오류

| 증상 | 해결 |
|---|---|
| 요구사항에 "잘", "적당히"가 계속 나온다 | 1단계의 표로 돌아가 낱말을 확인 가능한 문장으로 바꾼다. |
| "이런 결과"를 어떻게 쓸지 모르겠다 | 계산 결과를 숫자로 적는다. 예: `2와 3을 더하면 5` |
| 기능이 너무 많다 | 세 기능만 남기고 나머지는 "만들지 않는 것"으로 옮긴다. |

## 5. 확인 문제

1. "빠르게 계산한다"를 확인할 수 있는 문장으로 바꾸시오.
2. "잘못 쓰면" 칸이 왜 중요한가? 칸이 비어 있으면 AI 에게 어떤 일이 생기는가?
3. "만들지 않는 것"을 적는 이유를 한 문장으로 쓰시오.
4. 요구사항에 "어떻게 만들지"(예: 리스트를 쓴다)를 적으면 안 되는 이유는 무엇인가?
