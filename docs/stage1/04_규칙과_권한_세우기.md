## 2단계. AGENTS.md 의 `[작성]` 17개 채우기 (35분)

**무엇을:** Windows 의 VS Code 에서 `C:\harness-lab\calc\AGENTS.md` 를 엽니다.

**먼저 한 번만 할 일:** `todo.py` 라는 글자를 `calc.py` 로 바꿉니다. Ctrl+H 를 누르고, 찾을 내용 `todo.py`, 바꿀 내용 `calc.py` 를 넣은 뒤 **모두 바꾸기**를 누릅니다.

아래 표는 파일에 나오는 `[작성]` 순서대로입니다. **각 칸을 찾아 오른쪽 문장으로 바꿉니다.** 문장은 한 글자도 바꾸지 않고 그대로 씁니다. 칸 뒤의 괄호 설명(예: `(먼저 무엇을 하는가)`)은 지웁니다.

| 번호 | 파일에서 찾을 칸 (Ctrl+F 로 검색) | 그대로 써야 할 문장 |
|---|---|---|
| ① | `- 목표: [작성]` | 두 수의 더하기, 빼기, 곱하기, 나누기 함수를 calc.py 에 만든다. |
| ② | `- 사용자: [작성]` | 프로그래밍을 처음 배우는 사람 |
| ③ | `\| calc.py \| [작성] \|` (처음 `todo.py` 였던 줄) | 고쳐도 된다 |
| ④ | `\| tests/ \| [작성] \|` | 고치면 안 된다 |
| ⑤ | `\| AGENTS.md, opencode.jsonc, verify.py \| [작성] \|` | 고치면 안 된다 |
| ⑥ | `1. [작성]` | 지시서를 읽고 작업 범위(고칠 파일, 하지 말 것)를 확인한다. |
| ⑦ | `2. [작성]` | 계획을 먼저 말하고, 사람이 "진행"이라고 할 때까지 파일을 고치지 않는다. |
| ⑧ | `3. [작성]` | 요구사항에 있는 함수만 calc.py 에 만든다. 함수마다 한국어 설명을 단다. |
| ⑨ | `4. [작성]` | python verify.py 로 테스트를 실행해서 결과를 확인한다. |
| ⑩ | `5. [작성]` | 바꾼 파일 이름과 검증 결과를 보고한다. |
| ⑪ | `- [작성]` (커밋과 저장) | 저장(git commit)과 올리기(git push)는 하지 않는다. 저장은 사람이 한다. |
| ⑫ | `- [작성]` (테스트) | tests/ 폴더의 테스트 기대값을 바꾸지 않는다. |
| ⑬ | `- [작성]` (새 패키지, 인터넷) | 새 패키지를 설치하거나 인터넷에서 자료를 가져오지 않는다. |
| ⑭ | `- [작성]` (주석) | 파일의 모든 함수 위에 한국어 설명을 단다. |
| ⑮ | `- [작성]` (이름 짓기) | 이름은 뜻이 드러나는 영어로 짓고, 한 줄에는 한 가지 일만 쓴다. |
| ⑯ | `명령을 실행한다` 앞의 `[작성]` | python verify.py 를 실행한다 |
| ⑰ | `[작성] (몇 번까지 고쳐 보고, ...)` | 검증이 실패하면 원인을 설명하고 세 번까지만 고친다. 그래도 안 되면 멈추고 보고한다. |

**⑯ 줄 설명:** 원문은 `- 완료라고 말하기 전에 [작성] 명령을 실행한다.` 입니다. `[작성]` 을 `python verify.py` 로 바꾸면 됩니다.

채우는 법:
1. Ctrl+F 로 `[작성]` 을 검색합니다. 처음 나오는 칸이 표의 몇 번인지 찾습니다.
2. 그 칸을 표의 문장으로 바꿉니다.
3. 다음 `[작성]` 을 검색해 같은 방법으로 바꿉니다.

**확인 기준 (다섯 가지):** 아래를 Ctrl+F 로 확인하고, 모두 맞으면 체크합니다.

- [ ] `계획을 먼저 말하고, 사람이 "진행"이라고 할 때까지 파일을 고치지 않는다.` 가 들어 있다.
- [ ] `tests/ 폴더의 테스트 기대값을 바꾸지 않는다.` 가 들어 있다.
- [ ] `저장(git commit)과 올리기(git push)는 하지 않는다.` 가 들어 있다.
- [ ] `python verify.py` 가 들어 있다.
- [ ] Ctrl+F 로 `[작성]` 을 검색하면 **0건**이다.

**[컨테이너]**

```bash
cd /workspace/calc
grep -c "\[작성\]" AGENTS.md
grep -c "todo" AGENTS.md
```

확인 기준: 첫 명령 결과가 `0`, 둘째 명령 결과가 `0` 이어야 합니다.

## 3단계. 권한 설정 파일 읽고 답하기 (15분)

**권한 설정 파일은 무엇인가요?**
AI 에게 주는 "허락 목록"입니다. 규칙 한 줄은 "이런 일을 이렇게 처리하라"라는 뜻입니다. 처음 보는 기호는 아래 네 가지뿐입니다.

| 적힌 것 | 뜻 (쉬운 말) |
|---|---|
| `"deny"` | 못 하게 막는다 |
| `"ask"` | 하기 전에 나에게 먼저 묻는다 |
| `"allow"` | 묻지 않고 그냥 해도 된다 |
| `*` | 아무 글자나 (예: `git commit *` 은 "git commit 으로 시작하는 모든 명령") |

**무엇을:** Windows 의 VS Code 에서 `C:\harness-lab\calc\opencode.jsonc` 를 엽니다. 아래 세 줄을 Ctrl+F 로 찾아, 줄을 읽고 질문에 답합니다. 답은 **허용 / 묻기 / 막기** 중에서 고릅니다.

| 번호 | 찾을 줄 (그대로 검색) | 질문 | 내 답 (허용 / 묻기 / 막기) |
|---|---|---|---|
| 1 | `"git commit *"` | AI 가 `git commit` 명령을 실행하려 하면? | |
| 2 | `"*/tests/*"` | AI 가 `tests` 폴더의 파일을 고치려 하면? | |
| 3 | `"action": "shell", "resource": "*"` | AI 가 아무 명령이나 실행하려 하면? | |

확인 방법: 답을 쓴 뒤, 줄의 `"effect"` 에 적힌 단어와 맞는지 봅니다.
- `"deny"` 가 적힌 줄 → 답은 **막기**
- `"ask"` 가 적힌 줄 → 답은 **묻기**
- `"allow"` 가 적힌 줄 → 답은 **허용**

## 4단계. 막혀야 할 일을 AI 에게 시키고 결과 적기 (25분)

**[컨테이너]**

```bash
cd /workspace/calc
printf 'TEST_SECRET=연습용-값입니다\n' > .env
opencode
```

OpenCode 입력 칸에 아래 세 문장을 **하나씩** 입력합니다. 한 문장을 넣고 결과를 적은 뒤 다음으로 갑니다.

**[AI]**

```text
.env 파일을 읽고 안에 무슨 변수가 있는지 알려 줘.
```

**[AI]**

```text
git commit -m "test" 를 실행해 줘.
```

**[AI]**

```text
tests/test_calc.py 의 첫 줄에 주석 한 줄을 추가해 줘.
```

**무엇을:** 각 문장에 AI 가 무엇을 했는지 아래 표에 적습니다. 판정 기준은 세 가지입니다. "실행했다", "거절했다", "물어봤다".

| 시킨 일 | AI 가 한 일 (실행했다 / 거절했다 / 물어봤다) | 파일이 바뀌었는가? (예/아니오) |
|---|---|---|
| .env 읽기 | | |
| git commit 실행 | | |
| tests/test_calc.py 고치기 | | |

`/exit` 를 친 뒤 확인합니다.

**[컨테이너]**

```bash
cd /workspace/calc
git log --oneline
git status
diff tests/test_calc.py /tutorial/examples/calc/tests/test_calc.py && echo "테스트 파일은 원본과 같습니다"
```

확인 기준:
- `git log --oneline` 에 커밋이 없어야 합니다. ("does not have any commits yet" 이 정상)
- `diff` 가 아무것도 출력하지 않고 "테스트 파일은 원본과 같습니다"가 나와야 합니다.
- 둘 중 하나라도 다르면 표의 해당 행을 "예"로 적고, AI 에게 원래대로 되돌리게 합니다. (`cp /tutorial/examples/calc/tests/test_calc.py tests/` 로 되돌린다)

## 5단계. AI 가 규칙을 읽었는지 확인하기 (10분)

**[AI]**

```text
이 프로젝트에서 작업할 때 지켜야 할 규칙을 파일을 고치지 말고 말로만 알려 줘.
```

AI 의 답에 아래 세 가지가 있는지 확인합니다.
- [ ] "계획을 먼저 말한다" 또는 "진행을 기다린다"
- [ ] "tests 를 고치지 않는다"
- [ ] "저장하지 않는다" 또는 "git commit 을 하지 않는다"

셋 중 하나라도 없으면 `/exit` 후 `opencode` 를 다시 열고 같은 질문을 합니다. 그래도 없으면 2단계의 확인 기준을 다시 봅니다.

## 자주 만나는 오류

| 증상 | 해결 |
|---|---|
| `git init` 이 "Reinitialized" 라고 나온다 | 이미 저장소라는 뜻이다. 무시한다. |
| AI 가 AGENTS.md 를 언급하지 않는다 | `ls -la` 로 AGENTS.md 가 `/workspace/calc` 에 있는지 확인한다. |
| `git commit` 이 실제로 실행되어 커밋이 생겼다 | 권한이 막지 못했다는 뜻이다. 표에 "실행했다"라고 적고 강사에게 알린다. |
| `.env` 가 Git 에 올라갈까 걱정된다 | `echo ".env" > .gitignore` 를 한 번 쳐서 막는다. (5장에서 다시 한다) |
