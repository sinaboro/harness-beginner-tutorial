# 6장. 미니 프로젝트: 할 일 목록

| | |
|---|---|
| 시간 | 2시간 |
| 준비물 | 1~5장 완료. 템플릿(`templates/`) 과 요구사항, 지시서가 준비되어 있다 |
| 결과 | 할 일 목록 프로그램을 AI 에게 맡기고, 검증을 통과한 뒤 저장한다. 과정 기록을 쓴다. |

## 학습 목표

1. 지금까지 만든 다섯 가지(요구사항, 지시서, 규칙, 권한, 검증)를 한 프로젝트에 모두 쓴다.
2. 테스트가 정한 약속을 AI 가 지키게 만든다.
3. 저장 전에 검증이 통과했는지, 테스트 기준이 바뀌지 않았는지 직접 확인한다.
4. 내가 설명할 수 있는 코드만 저장한다.

---

## 1. 개념 — 지금까지의 고리

```text
 ① 요구사항 (REQUIREMENTS.md)     무엇을 만들지 약속한다         ← 2장
 ② 작업 지시서 (TASK_todo.md)     어디까지 맡길지 정한다         ← 3장
 ③ 규칙과 권한 (AGENTS.md, opencode.jsonc)  AI 의 행동 범위를 정한다  ← 4장
 ④ 실행과 검증 (tests/, verify.py)    맞는지 확인한다            ← 5장
 ⑤ 저장 (pre-commit, git commit)      통과한 것만 저장한다         ← 5장
```

이번 장에서 **사람이 하는 일**은 ①과 ②를 준비하는 것(템플릿이 해 줍니다), 계획 승인, 결과 검토, 저장입니다. 코드는 AI 가 씁니다.

## 2. 따라 하기

### 1단계. 미니 프로젝트 폴더 만들기 (15분)

**[PS]**

```powershell
New-Item -ItemType Directory C:\harness-lab\my-todo
cd C:\harness-lab\my-todo
New-Item -ItemType Directory tests
New-Item -ItemType Directory .githooks
```

템플릿을 가져옵니다.

**[PS]**

```powershell
$T = "C:\harness-beginner-tutorial\templates"
Copy-Item "$T\tests\test_todo.py" tests\
Copy-Item "$T\verify.py" .
Copy-Item "$T\opencode.jsonc" .
Copy-Item "$T\REQUIREMENTS.md" .
```

> `AGENTS.md` 는 4장에서 채운 내용을 쓰는 것이 원칙입니다. 4장을 건너뛰었다면 `templates\AGENTS_빈칸.md` 를 먼저 채우고 여기에 넣습니다.

### 2단계. 저장소 만들고 훅 켜기 (10분)

**[PS]**

```powershell

Set-Content .gitignore ".env"
```

이번 장에서는 **저장(커밋)을 마지막에 한 번만** 합니다. 지금 커밋하면 `todo.py` 가 없어서 검증이 실패하고 취소됩니다. 5장에서 본 장치라서 여기서는 하지 않습니다.

> 원본 테스트를 기준으로 남겨 둡니다. 나중에 테스트가 바뀌었는지 비교하려고 합니다.

### 3단계. 테스트 기준 읽기 (20분)

`tests/test_todo.py` 를 엽니다. 이 파일이 할 일 목록의 **약속**입니다.

**[PS]**

```powershell
code tests\test_todo.py
```

아래 세 가지를 찾아 적습니다.

1. `add_task` 가 돌려주는 값은 무엇인가?
2. 제목이 공백뿐이면 무엇이 일어나야 하나?
3. 파일이 없을 때 `load_tasks` 는 무엇을 돌려주나?

이 세 답이 곧 AI 가 지켜야 할 기준입니다.

### 4단계. 지시서와 계획 확인하기 (15분)

`TASK_todo.md` 와 `REQUIREMENTS.md` 를 읽습니다. 지시서의 "고쳐도 되는 파일"은 무엇입니까? "고치면 안 되는 파일"은 무엇입니까?

OpenCode 를 엽니다.

**[PS]**

```powershell
opencode
```

**[AI]**

```text
TASK_todo.md 를 읽고 그 지시대로 작업해 줘. AGENTS.md 의 작업 순서를 따라, 먼저 계획만 말하고 내 승인을 기다려.
```

AI 의 계획을 아래 체크리스트로 검토합니다.

- [ ] 고칠 파일이 `todo.py` 하나뿐인가?
- [ ] `tests/`, `verify.py`, `AGENTS.md` 를 고치겠다는 말이 없는가?
- [ ] 파일 저장 기능(R4)을 계획에 넣었는가?
- [ ] 외부 패키지를 설치하겠다는 말이 없는가?

맞으면 `진행` 이라고 답합니다. 맞지 않으면 다음처럼 고치게 합니다.

**[AI]**

```text
계획 3번에 웹 화면이 들어 있어. TASK_todo.md 의 "하지 말 것"에 있어서 빼고 다시 말해 줘.
```

### 5단계. 구현 지켜보기와 검증 (25분)

AI 가 `todo.py` 를 만드는 동안 지켜봅니다. 명령을 실행하기 전에 물어보면, 무엇을 하려는지 읽고 허락합니다. 허락은 `once` 만 씁니다.

끝나면 `/exit` 로 나오고, 검증을 직접 실행합니다.

**[PS]**

```powershell
python verify.py
```

- [ ] "검증 통과"가 나온다.
- [ ] 테스트 개수가 줄지 않았다.

검증이 실패하면, 실패 출력을 AI 에게 붙여 주고 **원인부터 설명하게** 합니다. 테스트를 고쳐서 통과시키라고 하지 않습니다.

**[AI]**

```text
python verify.py 가 실패했어. 아래가 출력이야. 원인을 먼저 설명하고, tests/ 는 건드리지 말고 todo.py 만 고쳐 줘.
(여기에 실패 출력을 붙여 넣는다)
```

> 세 번 고쳐도 통과하지 못하면 멈추고, `git restore todo.py` 로 되돌린 뒤 지시서를 더 작게 나눠서 다시 시킵니다. (새 파일은 `git status` 로 확인해 직접 지웁니다.)

### 6단계. 기준이 바뀌지 않았는지 확인하기 (10분)

**[PS]**

```powershell
git status
```

- [ ] 아래 비교 명령에 아무것도 나오지 않는다. (테스트 파일이 템플릿과 같다)
- [ ] `git status` 에 `todo.py` 가 새 파일로 나온다. 다른 파일은 새로 생기거나 바뀌지 않았다.

**[PS]**

```powershell
Compare-Object (Get-Content tests\test_todo.py) (Get-Content C:\harness-beginner-tutorial\templates\tests\test_todo.py)
```

비교 결과가 나오면 AI 가 기준을 고친 것입니다. 저장하지 않습니다. AI 에게 되돌리게 합니다.
(`git status` 에서 `tests/` 가 "새 파일"로 보이는 것은 정상입니다. 아직 한 번도 저장하지 않았기 때문입니다.)

### 7단계. 직접 실행해 보기 (10분)

테스트가 통과해도, 사람이 직접 써 봐야 합니다. 파이썬 대화 모드로 함수를 불러 봅니다.

**[PS]**

```powershell
python
```

```python
>>> from todo import add_task, complete_task, load_tasks, save_tasks
>>> tasks = []
>>> add_task(tasks, "우유 사기")
>>> complete_task(tasks, 1)
>>> tasks
>>> exit()
```

`tasks` 에 `done` 이 `True` 로 바뀐 것이 보이면 확인이 된 것입니다.

### 8단계. 설명할 수 있는지 확인하고 저장하기 (15분)

저장하기 전에, `todo.py` 를 위에서 아래로 읽으며 **세 문장으로 설명**해 봅니다.

1. 할 일 한 건은 어떤 모양의 자료인가?
2. 번호는 어떻게 정하는가?
3. 파일 저장과 읽기는 어떻게 하는가?

설명하지 못하는 부분이 있으면 AI 에게 묻습니다.

**[AI]**

```text
파일은 고치지 말고 설명만 해 줘. todo.py 의 add_task 에서 번호를 정하는 줄이 무슨 뜻이야? 초보자에게 두 문장으로 알려 줘.
```

설명을 이해했으면 저장합니다.

**[PS]**

```powershell
git add -A
git status
git commit -m "6장: 할 일 목록 완성 (R1~R4, 검증 통과)"
git log --oneline
```

`[pre-commit]` 이 통과하고 커밋이 한 줄 생기면 완료입니다.

- [ ] 계획 단계에서 범위 밖 기능을 하나 이상 빼게 했다.

## 4. 막혔을 때

| 증상 | 해결 |
|---|---|
| 테스트가 계속 실패한다 | 실패한 테스트 이름과 `assert` 줄을 AI 에게 붙여 주고 원인부터 설명하게 한다. |
| AI 가 테스트를 고치려 한다 | 권한 설정(`opencode.jsonc`)이 막는다. 막히지 않으면 `tests/` 를 되돌린다(`git restore tests/`). |
| 계획이 자꾸 범위를 넘는다 | `TASK_todo.md` 의 "하지 말 것"을 가리키며 빼게 한다. |
| 어디서부터 손대야 할지 모르겠다 | `tests/test_todo.py` 의 테스트를 하나씩 통과시킨다. 한 번에 다 하지 않는다. |

> 이 장에서는 **정답 코드를 제공하지 않습니다.** 답을 보기 전에 테스트와 지시서를 읽고, AI 와 대화하며 스스로 맞춰 가는 것이 목표입니다. 막히면 강사에게 물어보세요.

## 5. 확인 문제

1. `TASK_todo.md` 에서 "고치면 안 되는 파일"을 적은 이유는 무엇인가?
2. 이번 장에서 저장을 마지막에 한 번만 한 이유를 설명하시오.
3. 이번 장에서 **사람이 한 판단**을 세 가지 적으시오.
4. 테스트가 통과했는데도 직접 실행해 본 이유는 무엇인가?
5. 1장의 실험 A 와 이번 장을 비교했을 때, 달라진 점을 두 가지 쓰시오.
