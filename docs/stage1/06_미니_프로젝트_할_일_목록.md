# 1단계 6장. 미니 프로젝트: 할 일 목록

> **실행 환경: 도커.** 명령 블록은 컨테이너 안(bash)에서 칩니다. `[Windows]` 로 표시된 블록만 Windows PowerShell 에서 칩니다. 파일 편집은 Windows 의 VS Code 에서 합니다. 자세한 설명은 [도커로 실행하기](../docker/00_도커로_실행하기.md)를 봅니다.

| | |
|---|---|
| 시간 | 2시간 30분 |
| 준비물 | 1~5장 완료 |
| 결과 | 할 일 목록 프로그램 `todo.py` 를 AI 에게 맡기고, 테스트와 대조한 뒤 저장한다. 과정 기록을 쓴다 |

> 이 장은 **정답 파일을 주지 않습니다.** 요구사항과 테스트를 기준으로 확인합니다.

## 이 장에서 할 일 한눈에 보기

1. 새 작업 폴더를 만들고 파일을 가져온다. (15분)
2. 규칙 파일의 `calc.py` 를 `todo.py` 로 바꾼다. (10분)
3. 요구사항과 테스트 기준을 대조한다. (20분)
4. AI 에게 맡기고 계획을 검토한다. (25분)
5. 검증하고, 테스트 파일이 바뀌지 않았는지 확인한다. (20분)
6. 직접 실행해서 확인한다. (15분)
7. 기록을 쓰고 저장한다. (25분)

## 1단계. 새 작업 폴더 만들고 파일 가져오기 (15분)

**[컨테이너]**

```bash
mkdir -p /workspace/my-todo/tests /workspace/my-todo/.githooks
cd /workspace/my-todo
cp /tutorial/templates/tests/test_todo.py tests/
cp /tutorial/templates/REQUIREMENTS.md .
cp /tutorial/templates/TASK_todo.md .
cp /tutorial/templates/verify.py .
cp /tutorial/templates/opencode.jsonc .
cp /tutorial/templates/pre-commit .githooks/pre-commit
cp /tutorial/templates/.gitattributes .
cp /tutorial/examples/calc/pytest.ini .
cp /workspace/calc/AGENTS.md .
echo ".env" > .gitignore
git init
git config core.hooksPath .githooks
ls -la
ls tests
```

확인 기준: 아래 표의 파일이 모두 있어야 합니다.

| 파일 | 있는가? (예/아니오) |
|---|---|
| REQUIREMENTS.md | |
| TASK_todo.md | |
| AGENTS.md | |
| opencode.jsonc | |
| verify.py | |
| pytest.ini | |
| tests/test_todo.py | |
| .githooks/pre-commit | |

`git config core.hooksPath` 가 `.githooks` 를 출력해야 합니다.

## 2단계. AGENTS.md 를 이 프로젝트에 맞추기 (10분)

**무엇을:** 4장에서 만든 `AGENTS.md` 는 `calc.py` 를 가리킵니다. 이 프로젝트의 파일 이름 `todo.py` 로 바꿉니다.

**[Windows]** VS Code 에서 `C:\harness-lab\my-todo\AGENTS.md` 를 열고, Ctrl+H 로 `calc.py` 를 `todo.py` 로 **모두 바꾸기** 합니다.

**[컨테이너]**

```bash
cd /workspace/my-todo
grep -c "calc" AGENTS.md
grep -c "todo.py" AGENTS.md
```

확인 기준: 첫 명령 결과가 `0`, 둘째 명령 결과가 `1` 이상이어야 합니다.

## 3단계. 요구사항과 테스트 기준 대조하기 (20분)

**무엇을:** `REQUIREMENTS.md` 의 함수 이름과 `tests/test_todo.py` 의 함수 이름이 같은지 확인합니다.

**[컨테이너]**

```bash
cd /workspace/my-todo
grep -n "^### R\|add_task\|complete_task\|delete_task\|save_tasks\|load_tasks" REQUIREMENTS.md
grep -n "^from todo import" tests/test_todo.py
```

아래 표를 채웁니다.

| 요구사항 | 함수 이름 (REQUIREMENTS.md) | 테스트가 부르는가? (tests/test_todo.py 에서 찾는다) |
|---|---|---|
| R1 할 일 추가 | add_task | |
| R2 완료 표시 | complete_task | |
| R3 삭제 | delete_task | |
| R4 저장과 읽기 | save_tasks, load_tasks | |

확인 기준: 네 줄 모두 "예"여야 합니다. 아니오가 있으면 그 함수가 테스트에 없다는 뜻입니다. `REQUIREMENTS.md` 를 고치지 말고, 강사에게 알립니다.

## 4단계. AI 에게 맡기고 계획 검토하기 (25분)

**[컨테이너]**

```bash
cd /workspace/my-todo
opencode
```

OpenCode 입력 칸에 아래 문장을 **그대로** 입력합니다.

**[AI]**

```text
TASK_todo.md 를 읽고 그 지시대로 작업해 줘. REQUIREMENTS.md 와 tests/ 를 기준으로 삼는다. 먼저 계획만 말하고 내 승인을 기다려.
```

계획을 아래 네 질문으로 검토합니다.

| 질문 | 답 (예/아니오) | 아니오면 입력할 문장 |
|---|---|---|
| 1. 고치는 파일이 todo.py 한 개뿐인가? | | 아래 문장 A |
| 2. 계획에 tests/, verify.py, AGENTS.md 를 고친다는 말이 없는가? | | 아래 문장 A |
| 3. 계획에 R1~R4 의 함수가 모두 들어 있는가? | | 아래 문장 A |
| 4. 계획에 웹 화면, 데이터베이스, 날짜, 검색이 없는가? | | 아래 문장 A |

**[AI] 문장 A** (아니오일 때, 번호만 바꿔 입력합니다)

```text
계획 [번호]번이 TASK_todo.md 의 범위나 "하지 말 것"과 맞지 않아. 그 부분을 고쳐서 계획을 다시 말해 줘. 아직 파일은 만들지 마.
```

모두 예이면 입력합니다.

**[AI]**

```text
진행
```

끝나면 `/exit` 를 칩니다.

## 5단계. 검증하고 테스트 파일이 바뀌지 않았는지 확인하기 (20분)

**[컨테이너]**

```bash
cd /workspace/my-todo
python verify.py
python -m pytest -q
diff tests/test_todo.py /tutorial/templates/tests/test_todo.py && echo "테스트 파일은 원본과 같습니다"
git status
```

확인 기준:

| 확인할 것 | 기대하는 결과 | 실제 결과 (예/아니오) |
|---|---|---|
| 검증 결과 | 마지막 줄이 "검증 통과"다 | |
| 테스트 파일 | "테스트 파일은 원본과 같습니다"가 나온다 | |
| 바뀐 파일 | `git status` 의 새 파일이 todo.py 뿐이다 (AGENTS.md 등 다른 파일은 없다) | |

아니오가 있으면 AI 에게 그 항목을 알리고 고치게 합니다. 테스트 파일이 바뀌었다면 원본을 다시 복사합니다. `cp /tutorial/templates/tests/test_todo.py tests/`

**AI 에게 알리는 문장:**

**[AI]**

```text
python verify.py 결과가 [실패 줄 한 문장]이야. 원인을 먼저 설명하고, 내가 "진행"이라고 하면 todo.py 만 고쳐 줘. tests/ 는 고치지 마.
```

## 6단계. 직접 실행해서 확인하기 (15분)

**[컨테이너]**

```bash
cd /workspace/my-todo
python -c "
from todo import add_task, complete_task, delete_task, save_tasks, load_tasks
tasks = []
add_task(tasks, '우유 사기')
add_task(tasks, '운동하기')
complete_task(tasks, 1)
print(tasks)
delete_task(tasks, 2)
print(tasks)
save_tasks(tasks, 'tasks.json')
print(load_tasks('tasks.json'))
"
```

확인 기준:
- 첫 출력에서 1번 할 일의 `done` 이 `True` 여야 합니다.
- 둘째 출력에서 2번 할 일이 사라져야 합니다.
- 셋째 출력이 둘째 출력과 같아야 합니다.

**[컨테이너]**

```bash
rm -f tasks.json
```

## 7단계. 기록 쓰고 저장하기 (25분)

**무엇을:** `기록.md` 를 만들고 아래 질문에 한 문장씩 답합니다.

**[컨테이너]**

```bash
cd /workspace/my-todo
touch 기록.md
```

**[Windows]** VS Code 에서 `C:\harness-lab\my-todo\기록.md` 를 열고 아래 틀을 붙여 넣습니다.

```markdown
# 6장 기록

## 1. AI 에게 시킨 일 (TASK_todo.md 의 목표 칸을 그대로 옮긴다)
답:

## 2. 계획에서 고치게 한 것 (검토 네 질문 중 아니오였던 번호. 없으면 "없음")
답:

## 3. 검증에서 실패한 것과 고친 방법 (없으면 "없음")
답:

## 4. 내가 이해한 것 세 문장
1. (add_task 가 할 일을 어떻게 만드는지)
2. (complete_task 가 무엇을 바꾸는지)
3. (save_tasks 와 load_tasks 가 무엇을 맡는지)

## 5. 테스트가 통과해도 확인해야 하는 것 한 가지
답:
```

확인 기준: 모든 `답:` 뒤에 글자가 있어야 합니다. 확인:

**[컨테이너]**

```bash
grep -c "^답:\s*$" 기록.md
```

결과가 `0` 이면 저장합니다. 저장은 사람이 합니다.

**[컨테이너]**

```bash
cd /workspace/my-todo
python verify.py
git add -A
git status
git commit -m "6장: 할 일 목록 완성 (R1~R4, 검증 통과, 기록 작성)"
git log --oneline
```

확인 기준: `git status` 에 `tasks.json` 이 없어야 합니다. 커밋 과정에서 `[pre-commit]` 이 "검증 통과"를 출력해야 합니다.

## 막혔을 때

| 증상 | 해결 |
|---|---|
| `cp` 가 "No such file" 이라고 한다 | 파일 경로를 `ls /tutorial/templates` 로 확인한다. |
| 테스트가 `ImportError` 를 낸다 | todo.py 에 함수 이름이 빠졌다. 3단계 표의 함수 이름을 AI 에게 알리고 추가하게 한다. |
| AI 가 테스트를 고치려 한다 | 권한 설정이 막는다. 막히지 않았다면 `diff` 로 확인하고 원래대로 되돌린다. |
| 커밋이 `[pre-commit]` 에서 취소된다 | 실패 줄을 읽고 5단계의 AI 문장으로 원인부터 설명하게 한다. |

> 정답 코드는 제공하지 않습니다. 테스트 실패 줄을 하나씩 읽고, AI 와 대화하며 맞춰 갑니다.
