# 3장. 작업 지시서 쓰기

> **실행 환경: 도커.** 명령은 컨테이너 안(bash)에서 칩니다. 교안의 PowerShell 명령은 [도커로 실행하기](../docker/00_도커로_실행하기.md)의 명령 대응표(4절)를 보고 바꿔 씁니다. 편집은 Windows 의 VS Code 에서 합니다.

| | |
|---|---|
| 시간 | 2시간 |
| 준비물 | 2장의 요구사항, OpenCode 연결 완료 |
| 결과 | 지시서 여섯 칸을 채워 AI 에게 건네고, 계획을 검토해 승인한다 |

## 학습 목표

1. 작업 지시서의 여섯 칸(목표, 요구사항, 범위, 하지 말 것, 완료 조건, 진행 방법)을 설명한다.
2. 한 줄 지시와 지시서 지시의 결과를 비교한다.
3. AI 의 계획을 검토하고, 맞지 않으면 고치게 한다.

---

## 1. 개념 — 지시서는 "일을 나눠 주는 쪽지"

직장에서 일을 맡길 때 "알아서 해 주세요"라고만 하면 결과가 엉뚱하게 나옵니다. 목표, 범위, 하지 말 것, 끝났다는 기준을 말해 줘야 합니다. 작업 지시서는 그 내용을 글로 적은 것입니다.

| 칸 | 질문 | 빠지면 생기는 일 |
|---|---|---|
| 1. 목표 | 끝나면 무엇이 되어 있나? | 어디까지가 끝인지 모른다 |
| 2. 요구사항 | 어느 번호를 구현하나? | 기능의 모양을 AI 가 지어낸다 |
| 3. 범위 | 어떤 파일을 고쳐도 되나? | 관계없는 파일이 바뀐다 |
| 4. 하지 말 것 | 무엇을 덧붙이면 안 되나? | 시키지 않은 기능이 생긴다 |
| 5. 완료 조건 | 끝났다는 것을 어떻게 확인하나? | "다 했습니다"를 믿을 수밖에 없다 |
| 6. 진행 방법 | 계획을 먼저 말하는가? | 방향이 틀려도 끝난 뒤에야 안다 |

> **확인할 수 있는 문장으로 쓴다.** "잘 동작한다"는 확인할 수 없습니다. "`python verify.py` 가 검증 통과로 끝난다"는 확인할 수 있습니다.

## 2. 따라 하기

### 1단계. 빈칸 틀 복사하기 (5분)

**[PS]**

```powershell
New-Item -ItemType Directory C:\harness-lab\지시서연습
Copy-Item C:\harness-beginner-tutorial\templates\TASK_빈칸.md C:\harness-lab\지시서연습\지시서.md
notepad C:\harness-lab\지시서연습\지시서.md
```

### 2단계. 지시서 여섯 칸 채우기 (30분)

2장에서 쓴 계산기 요구사항을 바탕으로 채웁니다. 조건은 다음과 같습니다.

- 1번 목표: 계산기 파일 하나를 만든다.
- 2번 요구사항: 2장에서 정한 번호를 적는다.
- 3번 범위: 고쳐도 되는 파일은 `calc.py` 하나로 적는다.
- 4번 하지 말 것: 최소 두 가지를 적는다. (예: 화면, 파일 저장)
- 5번 완료 조건: "calc.py 를 `python calc.py` 로 실행하면 오류 없이 끝난다"와, 요구사항의 결과 두 개 이상을 적는다.
- 6번 진행 방법: 계획을 먼저 말하고 승인을 기다린다는 문장을 그대로 둔다.

### 3단계. 한 줄 지시와 비교하기 (20분)

1장의 실험 A 를 떠올립니다. 이번에는 지시서를 통째로 AI 에게 건넵니다. 폴더를 새로 만듭니다.

**[PS]**

```powershell
New-Item -ItemType Directory C:\harness-lab\calc3
cd C:\harness-lab\calc3
opencode
```

OpenCode 입력 칸에 다음을 붙여 넣습니다. `지시서.md` 의 내용을 그대로 붙여 넣어도 되고, 파일을 가리켜도 됩니다.

**[AI]**

```text
C:\harness-lab\지시서연습\지시서.md 를 읽고 그 지시대로 작업해 줘. 먼저 계획만 말하고 내 승인을 기다려.
```

> 파일 경로를 읽지 못하면, 지시서 내용을 직접 붙여 넣습니다.

### 4단계. 계획 검토하기 (20분)

AI 가 말한 계획을 아래 체크리스트로 검토합니다.

- [ ] 고칠 파일이 범위(3번)에 적힌 파일뿐인가?
- [ ] "하지 말 것"(4번)에 적힌 기능을 계획에 넣지 않았나?
- [ ] 완료 조건(5번)을 확인하는 방법을 말했나?
- [ ] 모르는 낱말이 있나? 있으면 지금 묻는다.

맞지 않으면 구체적으로 짚어서 고치게 합니다.

**[AI]**

```text
계획 2번에 나눗셈이 있어. 지시서 4번에서 "하지 말 것"에 적은 것과 맞지 않아. 빼고 계획을 다시 말해 줘.
```

맞으면 승인합니다.

**[AI]**

```text
진행
```

### 5단계. 결과 확인하기 (20분)

AI 가 일을 끝내면 지시서 5번(완료 조건)을 하나씩 직접 확인합니다.

**[PS]**

```powershell
cd C:\harness-lab\calc3
dir
python calc.py
```

- [ ] 파일이 지시서 3번 범위 안에 있다.
- [ ] 4번에 적은 기능이 없다.
- [ ] 5번의 결과가 실제로 나온다.

### 6단계. 한 줄 지시와 비교하기 (15분)

1장 실험 A 의 기록과 이번 결과를 나란히 놓고 표를 채웁니다.

| 항목 | 1장 실험 A (한 줄) | 3장 (지시서) |
|---|---|---|
| 계획을 먼저 말했나? | | |
| 시키지 않은 기능이 있나? | | |
| 완료 조건을 확인할 수 있었나? | | |
| 내가 결과를 판단하기 쉬웠나? | | |

## 3. 확인하기

- [ ] 지시서 여섯 칸을 모두 채웠다.
- [ ] AI 의 계획에서 빠진 부분이나 넘친 부분을 하나 이상 찾아 고치게 했다.
- [ ] 5번 완료 조건을 내 눈으로 확인했다.

## 4. 좋은 지시와 나쁜 지시

| 나쁜 지시 | 왜 나쁜가 | 좋은 지시 |
|---|---|---|
| "계산기 만들어 줘" | 목표와 범위가 없다 | "지시서대로 calc.py 를 만든다. 더하기와 빼기만 만든다." |
| "에러 고쳐 줘" | 어떤 에러인지 모른다 | "`python calc.py` 를 실행하면 이 오류가 난다. 원인을 먼저 설명하고 고쳐 줘." |
| "알아서 잘 해 줘" | 판단을 모두 AI 에게 넘긴다 | "두 방법이 있으면 장단점을 말하고 내가 고르게 해 줘." |

## 5. 자주 만나는 오류

| 증상 | 해결 |
|---|---|
| AI 가 지시서 파일을 못 찾는다 | 파일 경로를 확인하고, 내용을 직접 붙여 넣는다. |
| 계획 없이 바로 파일을 고친다 | "진행" 전에는 파일을 고치지 말라고 다시 말한다. 이미 고쳤다면 `/undo` 를 쓴다. |
| 지시서에 없는 기능이 들어간다 | 4번 "하지 말 것"을 가리키며 빼게 한다. |

## 6. 확인 문제

1. 작업 지시서의 여섯 칸을 순서대로 말하시오.
2. "완료 조건"을 "잘 동작한다"로 쓰면 어떤 문제가 생기는가?
3. "범위"와 "하지 말 것"의 차이를 설명하시오.
4. AI 에게 "먼저 계획만 말해"라고 하는 이유는 무엇인가?
