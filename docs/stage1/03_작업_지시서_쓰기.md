# 1단계 3장. 작업 지시서 쓰기

> **실행 환경: 도커.** 명령 블록은 컨테이너 안(bash)에서 칩니다. `[Windows]` 로 표시된 블록만 Windows PowerShell 에서 칩니다. 파일 편집은 Windows 의 VS Code 에서 합니다. 자세한 설명은 [도커로 실행하기](../docker/00_도커로_실행하기.md)를 봅니다.

| | |
|---|---|
| 시간 | 2시간 |
| 준비물 | 2장의 `요구사항.md` (`/workspace/req1`) |
| 결과 | 지시서 `지시서.md` 를 여섯 칸 워크시트로 완성하고, AI 의 계획을 검토해 승인한다. 결과를 지시서와 대조한다 |

## 이 장에서 할 일 한눈에 보기

1. 지시서 파일을 만든다. (5분)
2. 여섯 칸을 워크시트대로 채운다. (35분)
3. AI 에게 지시서를 건네고 계획을 받는다. (15분)
4. 계획을 네 질문으로 검토하고 승인한다. (20분)
5. 결과를 지시서와 대조한다. (20분)
6. 1장 실험 A 와 비교표를 채운다. (15분)

---

## 1단계. 지시서 파일 만들기 (5분)

**[컨테이너]**

```bash
mkdir -p /workspace/task1
cd /workspace/task1
touch 지시서.md
ls -la
```

**[Windows]** VS Code 에서 `C:\harness-lab\task1\지시서.md` 를 엽니다.

## 2단계. 여섯 칸 워크시트 채우기 (35분)

**무엇을:** `지시서.md` 에 아래 틀을 **그대로** 붙여 넣고, `[ ]` 칸을 채웁니다.

```markdown
# 작업 지시서: 계산기 만들기

## 1. 목표
[끝나면 무엇이 되어 있어야 하는지 한 문장]

## 2. 요구사항
[2장 요구사항.md 에서 만들 번호. 예: R1, R2]

## 3. 범위
- 고쳐도 되는 파일: [파일 이름 한 개]
- 고치면 안 되는 파일: [파일 이름 두 개. 예: 요구사항.md, 지시서.md]

## 4. 하지 말 것
- [하지 말아야 할 것 한 가지]
- [하지 말아야 할 것 한 가지]
- [하지 말아야 할 것 한 가지]

## 5. 완료 조건
- [ ] [확인할 수 있는 조건 한 가지]
- [ ] [확인할 수 있는 조건 한 가지]

## 6. 진행 방법
먼저 계획만 말한다. 내가 "진행"이라고 하기 전에는 파일을 만들거나 고치지 않는다.
끝나면 바꾼 파일 이름과 완료 조건을 확인한 결과를 보고한다.
```

칸별 워크시트 (아래 예를 참고해 **내 말로** 바꿉니다):

| 칸 | 무엇을 쓰나 | 예 |
|---|---|---|
| 1. 목표 | 파일 한 개와 함수 목록 | calc.py 에 더하기(add)와 빼기(subtract) 함수를 만든다 |
| 2. 요구사항 | 2장의 번호 | R1, R2 |
| 3. 고쳐도 되는 파일 | 파일 이름 한 개 | calc.py |
| 3. 고치면 안 되는 파일 | 파일 이름 두 개 | 요구사항.md, 지시서.md |
| 4. 하지 말 것 | 2장 "만들지 않는 것"에서 세 개 골라 쓴다 | 곱하기 함수를 만들지 않는다 / 화면을 만들지 않는다 / 파일을 저장하지 않는다 |
| 5. 완료 조건 (첫 줄) | 눈으로 볼 수 있는 조건 | `python calc.py` 를 실행하면 오류 없이 끝난다 |
| 5. 완료 조건 (둘째 줄) | 요구사항의 결과 한 개 | add(2, 3) 을 부르면 5가 나온다 |

확인 기준: 다음 세 가지를 보고, 아니오가 있으면 고칩니다.
- [ ] 6칸 중 `[` 가 남은 칸이 없다. (`grep -c "\[" 지시서.md` 결과가 `0`)
- [ ] 5번 완료 조건이 "잘 된다"처럼 흐리지 않다. 결과를 보고 맞다/아니다를 말할 수 있다.
- [ ] 4번 하지 말 것에 적은 내용이 2장 "만들지 않는 것"에 있다.

## 3단계. AI 에게 지시서 건네기 (15분)

**[컨테이너]**

```bash
cd /workspace/task1
opencode
```

OpenCode 입력 칸에 아래 문장을 **그대로** 붙여 넣습니다.

**[AI]**

```text
지시서.md 를 읽고 그 지시대로 작업해 줘. 먼저 계획만 말하고, 내가 "진행"이라고 할 때까지 파일을 만들거나 고치지 마.
```

AI 가 계획을 말하면 4단계로 갑니다. 이 시점에는 "진행"을 입력하지 않습니다.

## 4단계. 계획 검토하고 승인하기 (20분)

**무엇을:** AI 의 계획을 아래 네 질문으로 검토합니다.

| 질문 | 답 (예/아니오) | 아니오면 할 일 |
|---|---|---|
| 1. 고치는 파일이 calc.py 한 개뿐인가? | | 아래 문장 1번 |
| 2. 계획에 곱하기, 나누기, 파일 저장이 없는가? | | 아래 문장 2번 |
| 3. 계획이 요구사항.md 나 지시서.md 를 고친다고 하지 않는가? | | 아래 문장 3번 |
| 4. 계획에 더하기와 빼기가 모두 있는가? | | 아래 문장 4번 |

**아니오가 있으면** 아래 문장을 입력하고, 번호만 바꿉니다.

**[AI]**

```text
계획 중 [번호]번을 빼고, 다시 계획을 말해 줘. 아직 파일은 만들지 마.
```

모두 예이면 입력합니다.

**[AI]**

```text
진행
```

끝나면 `/exit` 를 칩니다.

## 5단계. 결과를 지시서와 대조하기 (20분)

**[컨테이너]**

```bash
cd /workspace/task1
ls -la
python calc.py
grep -c "def add\|def subtract" calc.py
grep -c "def multiply\|def divide" calc.py
```

**무엇을:** 아래 표를 채웁니다.

| 지시서의 항목 | 실제 결과 (위 명령의 출력) | 같은가? |
|---|---|---|
| 3번 고쳐도 되는 파일: calc.py 한 개 | `ls -la` 에 파일이 calc.py 만 새로 생겼는가? | |
| 4번 하지 말 것: 곱하기, 나누기 없음 | 둘째 `grep -c` 결과가 `0` 인가? | |
| 5번 완료 조건: 첫 줄 | `python calc.py` 가 오류 없이 끝났는가? | |
| 5번 완료 조건: 둘째 줄 | VS Code 에서 add 함수 설명대로 계산이 되는지 본다 | |

확인 기준: 표의 "같은가?" 칸이 모두 "예"여야 합니다. "아니오"가 있으면 AI 에게 그 항목 번호를 알리고 고치게 합니다.

**[AI]**

```text
지시서 [번호]번과 실제 결과가 달라. [실제로 본 것 한 문장]이야. 원인을 먼저 설명하고, 내가 "진행"이라고 하면 calc.py 만 고쳐 줘.
```

## 6단계. 1장 실험 A 와 비교하기 (15분)

|---|---|---|
| 계획을 먼저 말했는가? | | |
| 시키지 않은 기능이 있었는가? | | |
| 완료를 확인할 방법이 있었는가? | | |
| 결과를 지시서와 대조할 수 있었는가? | | |

비교 기준: 같은 항목의 두 칸에 "예/아니오"로 적습니다. 설명은 한 단어로 줄입니다.

## 확인 체크리스트
- [ ] `지시서.md` 의 여섯 칸을 모두 채웠다. `[` 가 0건이다.
- [ ] 계획 검토 네 질문에 모두 답했다.
- [ ] 5단계 표의 네 항목을 대조했다.
- [ ] 6단계 비교표를 채웠다.

## 자주 만나는 오류

| 증상 | 해결 |
|---|---|
| AI 가 `지시서.md` 를 찾지 못한다 | `cd /workspace/task1` 을 하고 `opencode` 를 쳤는지 확인한다. |
| AI 가 "진행"을 기다리지 않고 만든다 | 처음 입력한 문장에 "먼저 계획만 말하고"가 있었는지 확인한다. 이미 만들었다면 `/undo` 를 친다. |
| `python calc.py` 에서 오류가 난다 | 오류 문장을 적고, AI 에게 그 문장을 붙여 원인부터 설명하게 한다. |
