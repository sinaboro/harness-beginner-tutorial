# 1단계 5장. 검증하고 저장하기

> **실행 환경: 도커.** 명령 블록은 컨테이너 안(bash)에서 칩니다. `[Windows]` 로 표시된 블록만 Windows PowerShell 에서 칩니다. 파일 편집은 Windows 의 VS Code 에서 합니다. 자세한 설명은 [도커로 실행하기](../docker/00_도커로_실행하기.md)를 봅니다.

| | |
|---|---|
| 시간 | 2시간 |
| 준비물 | 4장의 `/workspace/calc` 폴더 (AGENTS.md, opencode.jsonc, verify.py 있음) |
| 결과 | 테스트가 빨강에서 초록으로 바뀌는 것을 보고, 검증을 통과해야만 커밋되도록 장치를 켠다 |

## 이 장에서 할 일 한눈에 보기

1. 정리하고 빨강을 확인한다. (15분)
2. AI 에게 `multiply` 함수를 추가하게 한다. (30분)
3. 초록을 확인하고 테스트 파일이 바뀌지 않았는지 대조한다. (15분)
4. 커밋 전에 검증하는 장치(훅)를 켠다. (10분)
5. 일부러 틀리게 고쳐 보고, 커밋이 막히는지 본다. (20분)
6. 되돌리고 정식으로 저장한다. (20분)

## 1단계. 정리하고 빨강 확인하기 (15분)

**[컨테이너]**

```bash
cd /workspace/calc
rm -f .env
echo ".env" > .gitignore
cp /tutorial/examples/calc/tests/test_calc.py tests/test_calc.py
git status
python -m pytest
```

확인 기준:
- `git status` 에 `.gitignore` 와 파일들이 보이고, `.env` 는 보이지 않아야 합니다.
- `python -m pytest` 의 출력에 `ERROR` 와 `ImportError` 가 있어야 합니다. 그 줄을 아래에 그대로 적습니다.

```text
(여기에 ImportError 줄을 옮겨 적는다)
```

**읽는 법:**
- `ERROR tests/test_calc.py` → 어느 파일에서 실패했나?
- `cannot import name 'multiply'` → 무엇이 없어서 실패했나?

테스트 파일은 `multiply` 를 쓰는 약속을 가지고 있지만, `calc.py` 에는 아직 `multiply` 가 없습니다. 이것이 **빨강**입니다.

> `python -m pytest` 와 `python verify.py` 는 같은 테스트를 실행합니다. `verify.py` 는 마지막에 "검증 통과" 또는 "검증 실패"를 한 줄로 알려 줍니다.

## 2단계. AI 에게 multiply 추가시키기 (30분)

**[컨테이너]**

```bash
cd /workspace/calc
opencode
```

OpenCode 입력 칸에 아래 문장을 **그대로** 입력합니다.

**[AI]**

```text
calc.py 에 multiply(a, b) 함수를 추가해 줘. 두 수를 곱한 결과를 돌려준다.
규칙:
1. 먼저 계획만 말하고, 내가 "진행"이라고 할 때까지 파일을 고치지 마.
2. tests/ 폴더와 verify.py 는 절대 고치지 마.
3. 끝나면 python verify.py 를 실행해서 결과를 보고해 줘.
```

AI 의 계획을 아래 세 질문으로 검토합니다.

| 질문 | 답 (예/아니오) | 아니오면 입력할 문장 |
|---|---|---|
| 1. 고치는 파일이 calc.py 한 개뿐인가? | | 아래 문장 A |
| 2. 계획에 tests/ 나 verify.py 를 고친다는 말이 없는가? | | 아래 문장 A |
| 3. 계획에 multiply 함수 추가가 들어 있는가? | | 아래 문장 A |

**[AI] 문장 A** (아니오일 때만, 번호만 바꿔 입력합니다)

```text
계획 [번호]번이 규칙과 맞지 않아. 그 부분을 빼고 계획을 다시 말해 줘. 아직 파일은 고치지 마.
```

모두 예이면 입력합니다.

**[AI]**

```text
진행
```

끝나면 `/exit` 를 칩니다.

## 3단계. 초록 확인하고 테스트가 바뀌지 않았는지 대조하기 (15분)

**[컨테이너]**

```bash
cd /workspace/calc
python -m pytest
python verify.py
diff tests/test_calc.py /tutorial/examples/calc/tests/test_calc.py && echo "테스트 파일은 원본과 같습니다"
grep -n "def multiply" calc.py
```

확인 기준:

| 확인할 것 | 기대하는 결과 | 실제 결과 (예/아니오) |
|---|---|---|
| 테스트 개수와 결과 | `5 passed` 가 나온다 | |
| 검증 결과 | 마지막 줄이 "검증 통과"다 | |
| 테스트 파일 대조 | "테스트 파일은 원본과 같습니다"가 나온다 | |
| 함수 확인 | `def multiply` 가 한 줄 나온다 | |

아니오가 있으면 AI 에게 그 항목을 알리고 고치게 합니다. 테스트 파일이 바뀌었다면, 원본을 다시 복사합니다. `cp /tutorial/examples/calc/tests/test_calc.py tests/`

**VS Code 에서 확인:** `calc.py` 를 열어 `multiply` 함수 위에 한국어 설명이 있는지 봅니다. 없으면 AI 에게 "multiply 함수 위에 한국어 설명을 달아 줘"라고 말합니다.

## 4단계. 커밋 전에 검증하는 장치 켜기 (10분)

**[컨테이너]**

```bash
cd /workspace/calc
mkdir -p .githooks
cp /tutorial/templates/pre-commit .githooks/pre-commit
cp /tutorial/templates/.gitattributes .
git config core.hooksPath .githooks
git config core.hooksPath
```

확인 기준: 마지막 명령이 `.githooks` 를 출력해야 합니다. 다른 것이 나오면 `git config core.hooksPath .githooks` 를 다시 칩니다.

## 5단계. 일부러 틀리게 고쳐서 저장이 막히는지 보기 (20분)

**[Windows]** VS Code 에서 `C:\harness-lab\calc\calc.py` 를 엽니다. Ctrl+H 로 `return a / b` 를 찾아 `return a + b` 로 바꾸고(**한 번만**, 나눗셈 함수 안의 줄), 저장합니다.

**[컨테이너]**

```bash
cd /workspace/calc
git add -A
git commit -m "실험: 틀린 나눗셈 저장 시도"
```

확인 기준: 출력에 아래 세 줄이 있어야 합니다.
- `[pre-commit] 저장하기 전에 검증을 실행합니다...`
- `FAILED tests/test_calc.py::test_divide`
- `[pre-commit] 검증 실패: 커밋을 취소했습니다.`

커밋이 생기지 않았는지 확인합니다.

**[컨테이너]**

```bash
git log --oneline
```

"does not have any commits yet" 이 나오면 정상입니다(아직 첫 커밋 전).

**[Windows]** 다시 VS Code 에서 `return a + b` 를 **`return a / b`** 로 되돌리고 저장합니다.

**[컨테이너]**

```bash
python verify.py
```

"검증 통과"가 나와야 다음 단계로 갑니다.

## 6단계. 정식으로 저장하기 (20분)

**[컨테이너]**

```bash
cd /workspace/calc
git add -A
git status
git commit -m "5장: multiply 추가, 테스트 통과 (검증 통과 후 저장)"
git log --oneline
```

확인 기준:
- `git status` 에 `.env` 가 없어야 합니다.
- `git log --oneline` 에 커밋이 한 줄 생겨야 합니다.
- 커밋 과정에서 `[pre-commit]` 이 "검증 통과"를 출력해야 합니다.

## 확인 체크리스트
- [ ] 빨강(ImportError)의 줄을 옮겨 적었다.
- [ ] `python verify.py` 가 "검증 통과"로 끝났다.
- [ ] 테스트 파일이 원본과 같다. (`diff` 가 아무것도 출력하지 않는다)
- [ ] 틀린 나눗셈을 커밋하려 했을 때 취소되는 것을 봤다.
- [ ] 되돌린 뒤 정식 커밋이 한 줄 생겼다.

## 자주 만나는 오류

| 증상 | 해결 |
|---|---|
| `No module named pytest` | 컨테이너를 다시 들어간다. 그래도 안 되면 `docker compose build` 를 Windows 에서 다시 한다. |
| `[pre-commit]` 이 나오지 않는다 | `git config core.hooksPath` 가 `.githooks` 를 출력하는지 본다. |
| 훅이 `python: command not found` | 컨테이너 안에서 커밋했는지 확인한다. Windows PowerShell 에서 커밋하면 안 된다. |
| `LF will be replaced by CRLF` 경고 | 기능에는 문제가 없다. 4단계에서 `.gitattributes` 를 복사했으므로 사라진다. |
| `git commit` 이 `Please tell me who you are` | `.env` 의 `GIT_NAME`, `GIT_EMAIL` 을 채우고 컨테이너를 다시 들어간다. |
