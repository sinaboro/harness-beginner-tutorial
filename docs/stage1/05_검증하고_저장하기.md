# 5장. 검증하고 저장하기

> **실행 환경: 도커.** 명령 블록은 컨테이너 안(bash)에서 칩니다. `[Windows]` 로 표시된 블록만 Windows PowerShell 에서 칩니다. 파일 편집은 Windows 의 VS Code 에서 합니다. 자세한 설명은 [도커로 실행하기](../docker/00_도커로_실행하기.md)를 봅니다.

| | |
|---|---|
| 시간 | 2시간 |
| 준비물 | 4장의 `/workspace/calc` 폴더 (AGENTS.md, opencode.jsonc, verify.py 포함) |
| 결과 | 테스트가 빨강에서 초록으로 바뀌는 것을 보고, 검증을 통과해야만 커밋되게 장치를 켠다 |

## 학습 목표

1. 테스트는 "약속"이며, 실행하면 약속을 지켰는지 알려 준다는 것을 설명한다.
2. 빨강(실패)과 초록(통과)의 의미를 말하고, 실패 출력을 읽는다.
3. 검증이 실패하면 커밋이 취소되는 것을 직접 본다.

---

## 1. 개념 — "돌아가는 것 같다"와 "통과했다"는 다르다

1장에서 AI 가 만든 계산기가 돌아가는 것처럼 보였습니다. 그러나 나눗셈에서 0으로 나누면 어떻게 되는지, 음수를 넣으면 어떤지는 확인하지 않았습니다. **화면에서 한 번 눌러 본 것은 확인이 아닙니다.**

테스트는 확인을 **코드로 적어 둔 것**입니다.

```python
def test_add():
    assert add(2, 3) == 5
```

- `assert` 뒤의 식이 **참**이면 통과(초록),
- **거짓**이면 실패(빨강)입니다.

### 빨강 → 초록 순서

```text
 1. 약속(테스트)을 먼저 본다              → 빨강: 아직 기능이 없다
 2. AI 에게 기능을 만들게 한다            → 구현
 3. 테스트를 다시 실행한다                → 초록: 약속을 지켰다
```

**테스트를 고쳐서 초록으로 만들면 안 됩니다.** 기준을 바꾸면 검증이 아닙니다.

## 2. 따라 하기

### 1단계. 정리하기 (10분)

4장에서 만든 연습용 `.env` 파일은 저장소에 올라가면 안 됩니다. 먼저 치웁니다.

**[컨테이너]**

```bash
cd /workspace/calc
rm -f .env
echo ".env" > .gitignore
git status
```

`git status` 에 `.gitignore` 만 새 파일로 보여야 합니다. 4장에서 AI 가 `tests/test_calc.py` 를 고쳤다면 되돌립니다. `git restore tests/` 를 쓰고, 그래도 바뀌어 있으면 강사에게 알립니다.

### 2단계. 빨강 확인하기 (15분)

테스트를 실행합니다.

**[컨테이너]**

```bash
python -m pytest
```

아래와 비슷한 빨간 출력이 나옵니다.

```text
ERROR tests/test_calc.py
E   ImportError: cannot import name 'multiply' from 'calc'
```

**읽는 법**
- `ERROR tests/test_calc.py` → 어느 파일에서 실패했나?
- `ImportError: cannot import name 'multiply'` → 무엇이 없어서 실패했나?

테스트 파일에는 `multiply` 를 쓰는 약속이 있지만, `calc.py` 에는 아직 `multiply` 가 없습니다. 이것이 **빨강**입니다.

> `python -m pytest` 와 `python verify.py` 는 같은 테스트를 실행합니다. `verify.py` 는 결과를 "검증 통과" 또는 "검증 실패"라는 한 줄로 알려 줍니다.

### 3단계. AI 에게 곱하기 추가시키기 (30분)

지시서를 짧게 씁니다. 테스트를 고치면 안 된다는 조건을 꼭 넣습니다.

**[컨테이너]**

```bash
cd /workspace/calc
opencode
```

**[AI]**

```text
calc.py 에 multiply(a, b) 함수를 추가해 줘. 두 수를 곱한 결과를 돌려준다.
규칙:
1. 먼저 계획만 말하고, 내가 "진행"이라고 할 때까지 파일을 고치지 마.
2. tests/ 폴더와 verify.py 는 절대 고치지 마.
3. 끝나면 python verify.py 를 실행해서 결과를 보고해 줘.
```

AI 의 계획을 확인하고 `진행` 이라고 답합니다. 끝나면 `/exit` 로 나옵니다.

**[컨테이너]**

```bash
python verify.py
git status
```

- [ ] `python verify.py` 가 "검증 통과"로 끝난다.
- [ ] `git status` 에 `tests/` 가 바뀐 것으로 나오지 않는다.
- [ ] `calc.py` 에 `multiply` 함수가 있고, 함수 위에 한국어 설명이 있다.

> 테스트 기대값(`assert multiply(4, 5) == 20`)을 AI 가 바꾸지 않았는지 꼭 봅니다. 아직 한 번도 저장하지 않았으므로 `git diff` 로는 볼 수 없습니다. 대신 원본과 비교합니다. 아무것도 나오지 않으면 같은 것입니다.
>
>**[컨테이너]**
>
> ```bash
> diff tests/test_calc.py /tutorial/examples/calc/tests/test_calc.py
> ```

### 4단계. 검증이 저장을 막는 장치 켜기 (20분)

이제 커밋하기 전에 검증을 자동으로 실행하는 장치(훅)를 설치합니다.

**[컨테이너]**

```bash
mkdir -p .githooks
cp /tutorial/templates/pre-commit .githooks/pre-commit
git config core.hooksPath .githooks
git config core.hooksPath
```

마지막 명령이 `.githooks` 를 출력하면 켜진 것입니다.

> 훅은 Git 이 `sh` 로 실행합니다. 컨테이너 안에 `sh`(bash)와 파이썬이 들어 있으므로 따로 설치할 것은 없습니다.

### 5단계. 일부러 깨뜨려 보고, 저장이 막히는 것 보기 (20분)

`calc.py` 의 `divide` 함수를 일부러 망가뜨립니다. VS Code 로 열어 `return a / b` 를 `return a + b` 로 바꾸고 저장합니다.

**[Windows]**

```bash
# (Windows) calc.py 을(를) VS Code 로 열어 고칩니다
```

그다음 저장을 시도합니다.

**[컨테이너]**

```bash
git add -A
git commit -m "실험: 깨진 코드 저장 시도"
```

아래와 비슷한 출력이 나오고, 커밋이 취소되어야 합니다.

```text
[pre-commit] 저장하기 전에 검증을 실행합니다...
...
FAILED tests/test_calc.py::test_divide - assert 12.0 == 3
검증 실패: 위의 오류를 고친 뒤 다시 실행하세요.
[pre-commit] 검증 실패: 커밋을 취소했습니다.
```

커밋이 생기지 않았는지 확인합니다.

**[컨테이너]**

```bash
git log --oneline
```

커밋 기록이 없어야 합니다. (아직 처음 커밋이므로 `does not have any commits yet` 메시지가 나와도 정상입니다.)

### 6단계. 고치고 정식으로 저장하기 (15분)

`divide` 를 원래대로 `return a / b` 로 되돌립니다. VS Code에서 고쳐도 되고, AI 에게 시켜도 됩니다.

**[컨테이너]**

```bash
python verify.py
```

"검증 통과"가 나오면 저장합니다.

**[컨테이너]**

```bash
git add -A
git commit -m "5장: multiply 추가, 테스트 통과 (검증 통과 후 저장)"
git log --oneline
```

이번에는 `[pre-commit]` 이 통과하고, 커밋 기록이 한 줄 생겼습니다.

## 3. 확인하기

- [ ] 빨강(ImportError)을 보고, 원인을 한 문장으로 말할 수 있다.
- [ ] AI 가 `multiply` 를 추가한 뒤 `python verify.py` 가 "검증 통과"로 끝났다.
- [ ] 깨뜨린 코드를 커밋하려 했을 때 취소되는 것을 봤다.
- [ ] 정식 커밋이 한 줄 생겼다.

## 4. 자주 만나는 오류

| 증상 | 해결 |
|---|---|
| `python -m pytest` 가 `No module named pytest` | 0장의 `python -m pip install pytest` 를 다시 실행한다. |
| `[pre-commit]` 이 나오지 않는다 | `git config core.hooksPath` 가 `.githooks` 를 출력하는지 확인한다. |
| 훅이 `python: command not found` | Python 이 PATH 에 없다. 0장을 다시 확인한다. |
| `LF will be replaced by CRLF` 경고가 뜬다 | 기능에는 문제가 없다. 템플릿의 `.gitattributes` 를 `calc` 폴더에 복사하면 사라진다. |
| `git commit` 이 `Please tell me who you are` | 0장 6절의 `git config --global` 두 줄을 다시 실행한다. |

## 5. 확인 문제

1. 테스트가 "약속"이라는 말을, `assert` 한 줄을 예로 들어 설명하시오.
2. 빨강에서 초록으로 가는 동안 **테스트 파일을 고치면 안 되는** 이유는 무엇인가?
3. 5단계에서 커밋이 취소된 이유를, 출력에 나온 `FAILED` 줄을 보고 설명하시오.
4. `verify.py` 가 실패하면 종료 코드 1 을 내는 이유는 무엇인가? (힌트: 훅이 이 값을 본다)
5. "화면에서 한 번 눌러 봤다"와 "테스트가 통과했다"의 차이를 말하시오.
