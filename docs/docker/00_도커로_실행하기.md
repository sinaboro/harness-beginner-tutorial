# 도커로 실행하기 (0·1·2단계 공통)

| | |
|---|---|
| 시간 | 1시간 (처음 한 번) |
| 준비물 | Windows 10·11, Docker Desktop, Git, VS Code |
| 결과 | Python, pytest, Git, OpenCode 가 든 작업 환경을 컨테이너로 실행한다 |

이 안내는 **0·1·2단계의 기본 실행 환경**입니다. PC 에 Python 과 OpenCode 를 직접 설치하지 않고, 컨테이너 안에서 과정을 진행합니다. 파일은 Windows 폴더에 두고 편집도 Windows 의 VS Code 에서 하므로, 평소처럼 파일을 보고 고칠 수 있습니다.

---

## 1. 개념 — 무엇이 어디에서 도는가

```text
 Windows (내 PC)                              컨테이너 (harness-beginner:1)
 ─────────────────────                       ──────────────────────────
 C:\harness-lab      ◀── 연결 ──▶            /workspace      (작업 폴더, 읽고 쓴다)
 C:\harness-beginner-tutorial ◀─ 연결 ─▶     /tutorial       (템플릿과 예제, 읽기 전용)
 VS Code (편집)                              bash, python, pytest, git, opencode
```

- **편집**은 Windows 의 VS Code 에서 합니다. 컨테이너 안에서 고친 파일도 Windows 에 바로 보입니다.
- **명령**은 컨테이너 안의 bash 에서 칩니다. 교안의 PowerShell 명령은 아래 표(4절)로 바꿔 씁니다.
- **OpenRouter 키**는 컨테이너 안에서 `opencode` 의 `/connect` 로 넣습니다. 컨테이너를 지워도 키는 남습니다(볼륨에 저장).

---

## 2. 따라 하기

### 1단계. Docker Desktop 설치 (20분)

1. https://www.docker.com/products/docker-desktop/ 에서 받아 설치합니다.
2. 설치 중 **Use WSL 2 instead of Hyper-V** 가 보이면 체크된 채로 둡니다.
3. PC 를 재시작하고 Docker Desktop 을 실행합니다. 왼쪽 아래가 **Engine running** 이 될 때까지 기다립니다.

확인합니다. PowerShell 을 새로 열고 칩니다.

**[PS]**

```powershell
docker version
```

Client 와 Server 두 줄이 모두 나와야 합니다. Server 가 나오지 않으면 Docker Desktop 이 덜 켜진 것입니다.

> WSL 오류가 나면 관리자 PowerShell 에서 `wsl --update` 를 실행하고 재부팅합니다. 가상화(BIOS 의 VT-x 또는 AMD-V)가 꺼져 있으면 켭니다.

### 2단계. 교안 저장소 받기 (5분)

**[PS]**

```powershell
git clone https://github.com/sinaboro/harness-beginner-tutorial C:\harness-beginner-tutorial
New-Item -ItemType Directory C:\harness-lab
cd C:\harness-beginner-tutorial\docker
Copy-Item .env.example .env
notepad .env
```

`.env` 에서 `GIT_NAME` 과 `GIT_EMAIL` 을 본인 것으로 바꾸고 저장합니다. 작업 폴더를 다른 곳으로 쓰려면 `HARNESS_LAB_DIR` 도 바꿉니다.

### 3단계. 이미지 만들기 (10~20분, 처음 한 번)

**[PS]**

```powershell
docker compose build
```

처음에는 Python 이미지를 내려받고 OpenCode 를 설치하느라 몇 분 걸립니다. 마지막 줄에 `Built` 또는 `Successfully` 가 보이면 됩니다.

### 4단계. 작업 환경 들어가기 (5분)

**[PS]**

```powershell
docker compose run --rm workspace
```

프롬프트가 `root@…:/workspace#` 로 바뀌면 컨테이너 안입니다. 확인합니다.

**[컨테이너]**

```bash
pwd
ls /tutorial/templates/stage0
python --version
python -m pytest --version
git --version
opencode --version
```

`/workspace` 는 `C:\harness-lab` 과 같은 폴더입니다. `/tutorial` 에는 교안 저장소의 템플릿과 예제가 보입니다.

나올 때는 `exit` 를 칩니다. 컨테이너는 `--rm` 덕분에 자동으로 지워지고, 파일과 OpenCode 연결 정보는 남습니다.

### 5단계. OpenRouter 연결 (5분)

**[컨테이너]**

```bash
opencode
```

입력 칸에 `/connect` 를 치고 **OpenRouter** 를 고른 뒤 키를 붙여 넣습니다. `/models` 로 목록이 나오면 `/exit` 로 나옵니다.

> 연결 정보가 실제로 남는지는 다음 번에 다시 들어가서 `opencode` → `/models` 로 확인합니다.

## 3. 폴더 대응표

| 교안에서 쓰는 Windows 경로 | 컨테이너 안의 경로 |
|---|---|
| `C:\harness-lab\card4` | `/workspace/card4` |
| `C:\harness-lab\calc` | `/workspace/calc` |
| `C:\harness-lab\my-todo` | `/workspace/my-todo` |
| `C:\harness-lab\library` | `/workspace/library` |
| `C:\harness-beginner-tutorial\templates` | `/tutorial/templates` (읽기 전용) |
| `C:\harness-beginner-tutorial\examples` | `/tutorial/examples` (읽기 전용) |

> 템플릿과 예제는 **읽기 전용**입니다. 복사해서 작업 폴더로 가져온 뒤 고칩니다. (교안의 `Copy-Item` 명령을 그대로 쓸 수 있습니다. 4절 표 참고)

## 4. PowerShell 명령을 컨테이너(bash)에서 쓰기

교안의 명령은 PowerShell 기준입니다. 컨테이너 안에서는 아래처럼 바꿔 씁니다.

| PowerShell (교안) | 컨테이너 bash | 하는 일 |
|---|---|---|
| `New-Item -ItemType Directory 폴더` | `mkdir -p 폴더` | 폴더 만들기 |
| `Copy-Item 원본 대상` | `cp -r 원본 대상` | 복사 |
| `Remove-Item 파일` | `rm -rf 파일` | 지우기 (되돌릴 수 없으니 주의) |
| `dir` | `ls -la` | 파일 목록 |
| `cd 폴더` | `cd 폴더` | 폴더 이동 |
| `notepad 파일` | VS Code 에서 연다 (Windows 쪽) | 편집 |
| `start index.html` | 탐색기에서 더블클릭 (Windows 쪽) | 브라우저로 열기 |
| `Set-Content .gitignore ".env"` | `echo ".env" > .gitignore` | 파일 내용 쓰기 |
| `Add-Content .gitignore "books.json"` | `echo "books.json" >> .gitignore` | 한 줄 덧붙이기 |
| `Compare-Object (Get-Content A) (Get-Content B)` | `diff A B` | 두 파일 비교 (아무것도 안 나오면 같음) |
| `Select-String "^def " library.py` | `grep "^def " library.py` | 줄 찾기 |
| `Get-Content 파일` | `cat 파일` | 내용 보기 |
| `python -m pytest`, `python verify.py`, `git ...` | 그대로 | 같은 명령 |

> 편집기(VS Code)와 브라우저 확인은 **Windows 쪽에서** 합니다. 컨테이너에는 화면이 없습니다.

## 5. 단계별로 시작하기

| 단계 | 컨테이너 안에서 먼저 할 일 |
|---|---|
| 0단계 | `mkdir -p /workspace/card4` 후, `/tutorial/templates/stage0` 의 파일을 `cp` 로 가져온다. 체크리스트 확인은 Windows 에서 브라우저로 한다. |
| 1단계 | `mkdir -p /workspace/calc` 후, `cp -r /tutorial/examples/calc/. /workspace/calc/`. 나머지는 교안과 같다. |
| 2단계 | `mkdir -p /workspace/library/tests` 후, 교안의 준비하기 3~4번을 bash 로 바꿔 실행한다. |

> 교안의 Windows 경로(`C:\harness-lab\…`)는 위 대응표로 `/workspace/…` 로 바꿔 읽습니다.

## 6. 자주 만나는 오류

| 증상 | 해결 |
|---|---|
| `docker compose` 가 `error during connect` | Docker Desktop 이 Engine running 이 아니다. 기다리거나 재시작한다. |
| `/workspace` 가 비어 있다 | `.env` 의 `HARNESS_LAB_DIR` 이 틀렸다. 슬래시(`/`)로 쓰고, 폴더가 있는지 본다. |
| `/tutorial` 이 비어 있다 | `TUTORIAL_DIR` 이 틀렸다. 교안 저장소를 `C:\harness-beginner-tutorial` 에 받았는지 확인한다. |
| `git commit` 이 `Please tell me who you are` | `.env` 의 `GIT_NAME`, `GIT_EMAIL` 을 채우고 `docker compose run` 을 다시 실행한다. |
| `opencode` 를 찾을 수 없다 | 이미지를 다시 만든다: `docker compose build --no-cache` |
| `/connect` 키가 다음 실행에 남지 않는다 | 볼륨이 연결되지 않았다. `docker volume ls` 로 `opencode-data` 가 있는지 본다. |
| 컨테이너 안에서 고친 파일 줄바꿈이 이상하다 | VS Code 오른쪽 아래의 `CRLF`/`LF` 표시를 확인한다. 저장소 설정은 LF 로 통일되어 있다. |
| `pytest` 가 파일을 못 찾는다 | 명령을 친 폴더가 맞는지 `pwd` 로 확인한다. 과제 폴더(`/workspace/calc` 등)에서 실행한다. |
